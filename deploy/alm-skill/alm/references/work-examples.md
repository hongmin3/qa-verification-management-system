# ALM에서 실제로 맡길 작업과 결과 예시

> 이 문서는 deploy/skill-examples.json에서 생성한다.

아래 내용은 요청과 결과 보고 형식 예시다. 현재 작업의 완료 사실이 아니다.

ALM은 기존 로그인된 Edge·Chrome과 Computer Use로 기록 업무를 수행하는 스킬입니다. 구체적인 실행 요청이면 대상 확인부터 저장 후 재조회까지 진행합니다. 사용법을 물으면 근거와 설명으로 답합니다. 아래 작업은 현재 제어 도구·대상 권한이 있을 때 수행하며, ZIP 설치만으로 브라우저 제어 기능이 생기지는 않습니다.

## 1. Checklist를 새 버전 TC와 미서명 문서로 등록

출처 구분: 이전에 요청한 V1.1.0 Checklist 신규 TC 이관 업무를 재구성

### 준비할 입력

- 최신 Checklist 파일·대상 시트·버전·등록할 A~K 범위와 보존할 실행 이력
- 로그인 브라우저·ALM 프로젝트·대상 Space·표준 문서·현재 Import 템플릿

### 복사해서 사용할 요청

```text
ALM과 VXvue 스킬로 최신 서버 Checklist의 [버전/시트]를 확인하고, 로그인된 Edge의 [프로젝트]에 A~K 정의를 신규 TC로 등록해줘.
기존 결과·버전·Issue 이력과 원래 빈 행은 보존해줘. 새 TC와 원본 행의 대응을 남기고 Preview에서 여러 Step이 하나의 TC로 묶이는지 확인해줘.
Import·SRS verifies 연결·[표준 문서] 기준 문서 편입·전체 재조회까지 진행해줘. 전자서명 없이 검토 가능한 문서까지 정리해줘.
```

### 수행할 범위

1. 현재 서버 자료 판과 원본 해시·시트·행·등록 대상을 다시 확인한다. 예전 제외 목록을 그대로 쓰지 않는다.
2. 현재 Import 열과 필수값을 확인하고 새 TC/Step 대응 자료를 만든다. Preview에서 묶음·Step/Expected·수량을 대조한 뒤 허용된 Import를 수행한다.
3. 생성한 ID와 원본 행을 연결하고 문서 편입·실제 SRS 관계를 확인한다. 기존 정상 서비스 API가 허용된 경우에만 대량 관계 처리에 병행한다.
4. 전체 대상의 속성·단계·Expected·문서 소속·관계를 다시 읽는다. 권한 제한과 불명확한 저장은 별도로 보고한다.

### 결과 보고 형식

```text
원본: [파일 해시 / 시트 / 행 범위]
등록: [생성 ID ↔ 원본 행 / 요청·생성·재조회 수량]
문서: [URL / 유형 / 표지·개정 이력 / 미서명 상태]
관계: [TC ID → verifies → SRS ID / 저장 대조 결과]
미완료: [권한 제한·누락·미서명 단계]
```

### 완료 기준과 제한

- 신규 Import와 Roundtrip을 구분한다. Old SRS ID 문자열만 적은 것은 관계 저장 완료가 아니다.
- Import 성공·Coverage·기존 Pass는 제품 시험 통과 증거가 아니다. Test Data 공란은 근거 없이 채우지 않는다.
- 원본이 바뀌면 기준본과 차이를 보고하고, 응답이 끊기면 생성 여부부터 조회해 중복 Import를 막는다.

## 2. 기존 TC의 속성과 Step·Expected 수정

출처 구분: 일반 브라우저 실행 요청 예시

### 준비할 입력

- 수정할 실제 TC ID·변경 전후 문구·수정할 필드
- 문서 상태·편집 권한·신규 생성인지 기존 갱신인지

### 복사해서 사용할 요청

```text
로그인된 Chrome의 [프로젝트]에서 [TC ID 목록]의 [변경할 필드]만 첨부한 전후표대로 수정해줘.
기존 ALM ID·문서 소속·Step/Expected 대응·실행 이력은 유지하고, 저장 후 같은 ID 전체를 다시 열어 대조해줘.
Excel을 사용하면 신규 Import가 아니라 기존 ID를 유지하는 Roundtrip인지 먼저 확인해줘.
```

### 수행할 범위

1. ID로 현재 항목과 상태·원래 값을 확인한다. 이미 값이 바뀌었으면 전후표와 충돌을 확인한다.
2. 허용된 필드만 수정한다. Roundtrip이면 내보낸 ID·행 구조와 현재 매핑을 보존한다.
3. 저장 뒤 같은 ID의 변경값·변경하지 않은 단계·관계·이력을 대조하고 추가 생성 여부를 확인한다.

### 결과 보고 형식

```text
대상: [TC ID / URL]
변경: [필드 / 이전 값 / 저장된 값]
보존: [단계 수·Step/Expected 대응·문서·실행 이력]
재조회: [전체 대상 대조 결과 / 불명확한 항목]
```

### 완료 기준과 제한

- 수정안을 제안해 달라는 요청만 받았다면 저장하지 않는다.
- 뜻이 바뀐 TC에 과거 Pass를 새 결과로 가져오지 않는다.

## 3. TC와 SRS의 실제 관계 연결

출처 구분: Checklist 이관에서 요청한 verifies 관계 작업을 재구성

### 준비할 입력

- TC↔SRS 매핑표·프로젝트·제품·버전·기존 관계
- 관계 방향과 추가/교체 범위

### 복사해서 사용할 요청

```text
ALM 스킬로 로그인된 Edge의 [프로젝트]에서 첨부 매핑의 TC와 SRS를 연결해줘.
TC의 verifies와 SRS의 is verified by 방향을 확인하고 기존 정상 관계는 유지해줘.
저장 뒤 양쪽 ID의 관계를 다시 읽어 요청한 매핑 전체와 대조해줘.
```

### 수행할 범위

1. 양쪽 실제 ID와 제품·버전·기존 관계를 읽고 연결할 의미가 맞는지 확인한다.
2. 요청한 방향으로 관계를 저장한다. 잘못된 기존 관계 삭제는 별도 요청 범위를 확인한다.
3. 양쪽 저장 관계와 요청 매핑을 대조하고 Coverage 표시와 실제 관계 저장을 구분해 보고한다.

### 결과 보고 형식

```text
매핑: [TC ID → verifies → SRS ID]
역방향: [SRS ID → is verified by → TC ID]
대조: [요청 / 기존 유지 / 추가 / 미저장 항목]
제품 커버리지 판단: [별도 검토 결과 또는 미검토]
```

### 완료 기준과 제한

- SRS ID의 존재만으로 해당 TC가 충분한 시험인지 확정하지 않는다.
- 403 등으로 읽지 못한 값은 공란이라고 단정하지 않고 현재 값 확인 불가로 남긴다.

## 4. Test Run 초안 생성과 포함 TC 확인

출처 구분: 일반 브라우저 실행 요청 예시

### 준비할 입력

- 프로젝트·Run 이름·템플릿·Plan Scope·대상 TC 목록
- 대상 빌드·파라미터·실행 환경·초기 상태

### 복사해서 사용할 요청

```text
ALM 스킬로 현재 로그인된 [브라우저]의 [프로젝트]에 [Run 이름] 초안을 만들어줘.
[템플릿]·[Plan Scope]·첨부 TC 목록·[빌드/환경]을 사용하고 생성 후 실제 포함 ID를 양방향 대조해줘.
시험은 수행하지 않았으므로 Passed나 실행 결과는 입력하지 마.
```

### 수행할 범위

1. 템플릿과 Plan Scope·현재 TC 목록을 확인하고 중복 Run 여부를 조회한다.
2. 요청한 설정으로 Run을 생성한다.
3. 같은 Run ID를 다시 열어 포함/누락/초과 TC와 파라미터·초기 상태를 확인한다.

### 결과 보고 형식

```text
Run: [생성 ID / URL / 이름]
범위: [Plan Scope / 요청·포함·누락·초과 TC]
환경: [빌드 / 파라미터 / 실행 환경]
상태: [재조회한 초기 상태 / 시험 결과 미입력]
```

### 완료 기준과 제한

- 템플릿 예시를 현재 프로젝트의 필수값으로 단정하지 않는다.
- Run 초안 생성은 실제 시험 수행이나 제품 Pass가 아니다.

## 5. 근거가 있는 Issue 등록 또는 지정 항목 수정

출처 구분: 기존 이슈 초안 작성 흐름을 실제 등록 요청으로 확장한 예시

### 준비할 입력

- Actual 캡처·로그·재현 절차·발생 버전·Expected 근거
- 등록 프로젝트·유형·담당자·연결할 TC/Run·기존 유사 이슈

### 복사해서 사용할 요청

```text
VXvue 스킬로 첨부 현상의 Expected와 기존 유사 이슈를 먼저 확인하고, ALM 스킬로 [프로젝트]에 Issue를 등록해줘.
제공한 Actual과 재현 절차만 쓰고, 확인하지 않은 원인·횟수·등급은 확정하지 마.
제목·본문·버전·담당자·첨부·[TC/Run] 연결을 저장하고 생성 ID에서 다시 확인해줘.
```

### 수행할 범위

1. 실제 관찰과 문서상 Expected·미확인을 나누고 기존 유사 이슈를 확인한다.
2. 등록 범위와 필요한 값이 확인된 뒤 요청한 Issue를 생성하거나 지정 ID만 수정한다.
3. 저장된 제목·본문·버전·첨부·관계와 ID를 재조회한다.

### 결과 보고 형식

```text
Issue: [ID / URL / 신규 또는 수정]
근거: [Actual 증거 / Expected 출처 / 미확인 원인]
저장 확인: [제목·본문·버전·담당자·첨부·관계]
미완료: [권한 또는 자료 부족]
```

### 완료 기준과 제한

- 초안만 요청한 경우에는 등록하지 않는다. 근거가 불충분하면 결함 확정 대신 확인 필요로 보고한다.
- 메일 발송·다른 이슈 상태 변경은 이 요청에 포함하지 않는다.

## 6. 표준 문서 구성과 미서명 상태 정리

출처 구분: Basic Function 기준 문서 정리 요청을 재구성

### 준비할 입력

- 대상 Space·문서명·유형·포함 Work Item 목록
- 참조할 표준 문서·표지·결재표·개정 이력·현재 결재경로 권한

### 복사해서 사용할 요청

```text
ALM 스킬로 [표준 문서]를 참고해 [대상 Space]에 [문서명]을 구성하고 첨부 TC ID를 순서대로 넣어줘.
표지·결재표·개정 이력과 실제 결재경로 속성은 각각 확인해줘.
전자서명을 하지 않은 검토용 문서까지 정리하고 목차·Heading·포함 ID를 저장 후 재조회해줘.
```

### 수행할 범위

1. 현재 문서 유형과 표준 문서의 구조를 확인한다. 결재표 본문과 실제 approvalType 같은 속성을 구분한다.
2. 요청한 표지·Heading·항목 편입을 수행하고 문서를 저장한다.
3. 포함 ID 전체·순서·목차·표지·현재 미서명 상태를 확인한다.

### 결과 보고 형식

```text
문서: [URL / 유형 / Space]
구성: [Heading / 포함 ID / 순서 대조]
결재: [표지 결재표 / 실제 경로 조회 결과 / 미서명 상태]
남은 작업: [권한 부족 설정 / 사용자 검토·서명]
```

### 완료 기준과 제한

- 권한이 없어 읽지 못한 결재경로는 빈 값으로 보고하지 않는다.
- 표지 정리와 최종 결재 완료는 다르다.

## 7. 제공한 시험 증거를 지정 Run에 기록

출처 구분: 사용자의 “검증했어·수정확인했다” 후속 요청을 재구성

### 준비할 입력

- 실제로 수행한 버전·TC·조건·Actual·증거·판정
- 대상 Run·Iteration·Step별 결과·Issue와 과거 이력

### 복사해서 사용할 요청

```text
첨부한 수행 증거를 VXvue 스킬로 기존 TC와 대조하고, ALM 스킬로 [Run ID]의 [TC/Iteration]에 이번 결과를 기록해줘.
내가 준 조건과 결과만 사용하고 과거 Fail·재발생 기록은 유지해줘.
Step별 결과와 전체 상태를 구분해 재조회하고, 증거가 부족한 항목은 입력을 보류해줘.
```

### 수행할 범위

1. 현재 Run·버전·TC·Iteration을 확인하고 실제 증거와 판정 기준을 대조한다.
2. 허용된 이번 실행 기록만 입력하고 증거와 Issue를 연결한다.
3. 같은 실행 기록의 Step·전체 상태·증거·이력 보존을 확인한다.

### 결과 보고 형식

```text
실행 대상: [Run / TC / Iteration / 빌드]
기록 근거: [실제 수행 조건 / Actual / 증거]
저장 결과: [Step별 결과 / 전체 상태 / Issue]
보류: [증거 또는 판정 기준이 부족한 항목]
```

### 완료 기준과 제한

- 개발팀 수정 완료·Coverage·문서 작성만으로 Passed를 입력하지 않는다.
- 사용자가 “검증했어”라고만 하면 무엇을 어떤 조건에서 확인했는지 자료와 현재 기록으로 먼저 확인한다.

## 8. 실행 전에 절차와 필요한 자료만 물어보기

출처 구분: 설명·조사 전용 요청 예시

### 준비할 입력

- 알고 싶은 업무·대상 제품·버전·현재 상태

### 복사해서 사용할 요청

```text
ALM 스킬로 신규 Import와 Roundtrip의 차이, 준비할 파일과 Preview에서 확인할 내용을 알려줘.
이번에는 설명과 근거 조회만 하고 브라우저의 기록을 변경하지 마.
```

### 수행할 범위

1. 현재 자료 판의 관련 장·슬라이드·영상 근거를 읽는다.
2. 업무 차이와 필요한 입력·실행 시 확인할 항목을 정리한다.
3. 현재 운영 설정을 확인하지 못한 부분과 아직 수행하지 않은 작업을 알린다.

### 결과 보고 형식

```text
설명: [절차 차이 / 선택 기준]
근거: [가이드 장 / 슬라이드 / 영상 시점]
준비할 자료: [필요 입력]
```
