# 로그인된 브라우저에서 Teamcenter 작업하기

구체적인 등록·수정·첨부·DHF 연결 요청에만 적용한다. 자료 조사·가이드 작성·준비 요청에는 쓰기를 추가하지 않는다.

## 연결과 대상

현재 환경의 Computer Use 스킬과 도구 설명을 읽고 사용자가 지정한 기존 Edge·Chrome 탭을 사용한다. 서버·프로젝트·객체 유형·문서 ID·리비전·상태·선택 행을 현재 화면에서 확인한다. 창 제목과 실제 화면이 다르거나 연결이 불확실하면 입력하지 않고 미수행 범위를 알린다. 새 자동화 프로필로 대체하거나 쿠키·토큰·비밀번호를 추출하지 않는다. 기존 탭과 미저장 편집을 보존한다.

## 준비와 작업 경계

서버 가이드에서 현재 자료 판을 고정해 해당 장과 17장 미확정 항목을 읽는다. 신규 문서인지 기존 리비전 수정인지, 모델별 승인 위치·DHF 적용 여부·첨부할 실제 파일·문서번호·문서 주제·Priority Grade를 확인한다. 화면과 자료로 알 수 있는 내용을 다시 묻지 않는다. 결과를 바꾸는 대상 정보가 없으면 쓰기 전에 질문한다.

ALM 승인 PDF는 ALM 스킬과 실제 승인 상태·Export PDF의 문서번호·쪽수·내용을 확인한다. 승인 전 문서를 PLM 자가승인으로 대신하지 않는다. `10.Document Approve(V2)`와 `100.Document Approve(ALM)`의 대상과 리비전을 확인한다.

전자서명은 사용자가 직접 처리한다. 자가승인·최종 승인은 사용자에게 넘긴다. WBS의 일반 완료는 요청·실제 작업 내용·승인 레퍼런스·선행 조건을 확인한 범위에서 수행하고 같은 타스크의 최종 상태를 재조회한다. 서명·결재가 필요하면 사용자에게 넘긴다. Workflow 제출 요청은 올바른 템플릿·타깃·결재자를 준비한 뒤 현재 도구의 확인 정책을 따른다. 삭제·기존 첨부 교체·개정은 요청 범위를 확인하고 이전 문서와 관계를 보존한다. 이미 요청한 일반 저장마다 허락을 반복해서 묻지 않는다.

## 저장 후 재조회

| 작업 | 같은 객체에서 다시 확인할 것 |
|---|---|
| 문서번호 등록 | 새 ID·리비전·유형·이름·문서 주제·Priority Grade·중복 여부 |
| 파일 첨부 | 대상 ID·파일명·PDF 내용·문서번호·쪽수·체크인 상태 |
| 개정과 교체 | 이전/새 리비전·첨부·승인 상태·기존 DHF 연결 영향 |
| DHF 연결 | 프로젝트·Record·승인 문서 ID/리비전·Record Deliverable Relation |
| TC 저장 위치 입력 | 문서번호·리비전·실제 저장 위치·요청하지 않은 파일 미첨부 |
| WBS 저장·일반 완료 | 타스크 ID·담당자·작업 내용·승인 레퍼런스·요청한 완료 또는 보류 상태 |

저장 후 문서 ID로 같은 객체를 다시 열어 실제 값과 관계를 읽는다. Save·업로드 후 응답이 끊기면 생성 여부부터 조회한다. 확인 없이 재저장해 중복을 만들지 않는다. 불명확한 결과는 불명으로 남기고 추가 쓰기를 멈춘다. DHF 승인 완료 시 연구소의 리비전이 필요한 교육 지침과 현재 상태를 확인한다.

## 보고

대상 서버·프로젝트·ID·리비전·변경 전후·재조회한 값·첨부 및 관계·미수행 항목을 보고한다. 파일 준비·입력·저장·재조회·사람 승인 단계를 구분한다. 과거 영상·샘플·가이드와 현재 Teamcenter 실행 증거를 구분하고 수행하지 않은 승인·제품 Pass를 기록하지 않는다.

## 작업별 예시와 보고

[업무 요청과 결과 예시](work-examples.md)는 입력·실행 단계·결과 보고 형식·미완료 기준을 제공한다. 구체적인 요청에는 예시를 설명하는 데서 끝내지 않고 현재 대상에서 허용된 동작을 진행한다. 설명·검토·준비 요청은 그 범위를 지킨다.

보고는 `대상 → 요청한 작업 → 수행한 조작 → 재조회한 값과 증거 → 미완료·이유 → 다음 담당자` 순서로 작성한다. 저장·관계·첨부·최종 상태를 각각 확인하고 화면에 보이는 객체 ID와 리비전/실행 번호를 남긴다. 예시의 완료 문구를 실제 실행 없이 복사하지 않는다.
