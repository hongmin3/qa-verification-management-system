# QA Agent 화면·실행 상태·결과

> 상위: [문서 지도](../README.md) · 사용법: 앱 안 `/qa-agent/guide` · [사용 안내](../USER_GUIDE.md) · [엔진](daily-qa.md) · [사양](../../specs/qa-intelligence.md)

QA 담당자가 제품별 사양·이슈 변경과 현재 이슈 상태를 확인하는 화면이다. 서버가 수집한 자료와 분석 결론·근거·QA 할 일을 대시보드와 상세 화면으로 보여준다. TC 점검과 검증 TC 초안은 결과 화면에서 사람이 요청한다.

## 화면과 실행 경계

| 주소 | 역할 |
|---|---|
| `/qa-agent` | 제품 선택, 자동 점검 모드, 현재 실행, 결과 요약 |
| `/qa-agent/status` | 공용 진행 표시가 읽는 제품별 실행 상태 |
| `/qa-agent/runs` (POST) | [지금 실행]으로 선택한 기간 분석 시작 |
| `/qa-agent/issue-audit` (POST) | 변경 기록이 없는 기간의 현재 이슈 상태 점검 |
| `/qa-agent/runs/<실행 ID>` | 실행 단계·실패 사유·저장 결과·사용량 |
| `/qa-agent/runs/<실행 ID>/findings` | 실행의 전체 결과 목록과 페이지 이동 |
| `/qa-agent/runs/<실행 ID>/cancel` (POST) | 현재 제품 실행에 중단 요청 |
| `/qa-agent/findings/<번호>` | 근거·QA 할 일·수동 TC 작업 요청 |
| `/qa-agent/period` | 기간별 저장 결과 조회 |
| `/qa-agent/automation-policy` (GET·POST) | 제품별 자동 점검 설정 조회·저장 |
| `/qa-agent/rules` | 제품 규칙의 현재 구현 범위 |
| `/qa-agent/guide` | 화면 조작 방법 |

웹 요청은 별도 점검 프로세스를 시작한다. 분석 순서는 `app/modules/daily_qa/pipeline.py`, 화면과 요청 처리는 `app/modules/qa_agent/`가 맡는다. 웹 서비스 프로세스 안에서 Claude 분석을 수행하지 않는다.

## 진행과 중단

대시보드와 결과 상세의 진행 표시는 같은 상태 JSON을 읽는다. 다른 브라우저로 들어와도 공유 실행의 단계·경과 시간·완료 수를 본다. 수집 실패, 사용량 한도, 분석 실패와 사용자 중단은 서로 구분한다.

[분석 중단]은 현재 제품과 실행 번호를 확인한 뒤 요청한다. 메일 단계에 들어간 실행과 이미 끝난 실행은 중단할 수 없다. 중단된 실행은 `CANCELLED`로 남고 이미 저장한 수집 자료·결과·사용량을 보존한다. 미처리 이벤트는 대기로 남으며 중단 메일은 보내지 않는다(REQ-QAINTEL-036).

실행 상세는 처음에 대표 결과 10건을 보여주고 전체 목록은 접어서 제공한다. 전체 결과는 별도 목록에서 페이지로 읽는다. 작업 입력과 모델·추론 정도, 호출 수·토큰·비용은 실행에 기록된 값으로 확인한다. 성공 결과를 다시 썼으면 원본 실행과 재사용 수, 새 Claude 호출 수를 구분한다(REQ-QAINTEL-037).

## 자동 점검 설정

[자동 점검 사용]과 [검증 기간]을 저장해 일일·주간·중지를 선택한다. 일반 사내 웹에서 설정을 변경할 수 있고, 제품별 값과 변경 이력은 공용 DB에 남는다. 자세한 정책은 [엔진 문서](daily-qa.md#자동-점검-모드)와 REQ-QAINTEL-038을 따른다.

서버의 `daily_qa.schedule.enabled: false`는 자동 실행보다 우선한다. 담당자 PC의 예약 비활성화는 화면 설정으로 켤 수 없다. 자동 중지는 진행 중인 분석을 강제로 종료하지 않으며 다음 자동 실행과 메일을 막는다. 수동 실행은 가능하다.

AI 모델·추론 정도는 공용 모델 설정 화면에서 읽는다. 저장은 서버 안에서 직접 접속했을 때만 허용하며 프록시 헤더가 있는 요청은 거절한다(REQ-AICALL-007). 자동 점검 모드의 사내 웹 저장 허용과 구분한다.

## 공용 자료와 데이터

- 제품 설정·제품 규칙 Skill과 공용 Knowledge를 현재 분석에서 사용한다. `app/core/qa_rules.py`의 규칙 읽기·발췌와 `/rules` 화면은 유지한다.
- `app/modules/qa_agent/polarion_issue.py`는 공용 식별자·본문 구획·HTML 텍스트 유틸을 제공한다. 일일 QA에서도 사용하는 파일이므로 유지한다.
- `app/modules/qa_agent/schemas.py`의 공용 Regression 축·표시 이름·설명은 현재 결과와 사용법에서 유지한다. 현재 분석의 결과 형식은 `app/modules/daily_qa/schema.py`가 검사한다.
- 분석 결과의 번호와 근거가 현재 자료에 있는지는 `app/modules/daily_qa/evidence_validation.py`로 확인한다. Polarion은 읽기 전용이며 최종 QA 판단과 원본 수정은 사람이 한다.

## 단일 이슈 분석 사용 종료

2026-10-13부터 단일 이슈 분석의 전용 화면·API·분석 엔진·프롬프트·모델 비교 명령을 제공하지 않는다(REQ-QAAGENT-016). 옛 주소 `/qa-agent/issue-analysis`와 `/qa-agent/analyses` 등은 404이며 AI 호출이나 새 작업을 만들지 않는다.

과거 분석·입력·결과·승인·사용량 기록은 DB에서 지우지 않는다. 폐기된 기능의 대기 작업은 실패 상태로 끝내며 재개하지 않는다. 기존 요구사항의 ID와 본문은 [SPEC](../../SPEC.md)의 폐기 기록으로 남는다. 현재 점검·기간 조회·수동 TC 작업·제품 지식 수집은 계속 제공한다.
