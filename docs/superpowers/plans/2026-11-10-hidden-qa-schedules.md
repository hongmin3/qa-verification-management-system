# QA 예약의 창 숨기기와 요청 확인 주기 변경

사용자가 CMD 창 숨기기와 요청 확인 5분 주기를 승인했다. 기존 작업 사본에서 직접 실행한다.

## 범위와 확인한 근거

- 기존 `QA_LimitEvidence_Sync`는 `pythonw.exe`와 `CREATE_NO_WINDOW`를 사용한다. 같은 실행 방식을 재사용한다.
- `scripts/install_product_knowledge_schedule.ps1`·`scripts/install_bellalun_shared_schedule.ps1`는 콘솔 Python과 1분 주기를 사용한다. `REQ-SYNC-002`·`REQ-KNOW-021`·`REQ-KNOW-024`·`REQ-BELLALUNSHARED-006`이 관련된다.
- 요청 없는 실행을 창 없이 측정하니 Bellalun 1.455초·VXvue 1.309초였다. 제품 원문 스캔·전체 동기화는 실행되지 않았다.
- 매일 10:00/10:10 동기화·15분 재시도·기존 계정·시작 위치·인수·인증은 보존한다. 화면 요청 확인만 5분으로 바꾼다.

## 실행 순서

1. 사양의 요청 확인 시간을 5분으로 바꾸고 숨김 실행·오류 기록을 명시한다.
2. 합성 자식 프로세스로 인수·종료 코드·오류 기록·Windows 콘솔 없음 검사를 먼저 실패시킨다.
3. `scripts/run_scheduled_python.py`에 창 없는 자식 실행과 실패 로그를 구현한다. 기존 설치기와 Skill 예약 안내를 연결한다.
4. 관련 테스트와 로컬 준비 검사를 실행한다. 기존 예약 XML을 백업하고 동작 및 두 요청 확인 트리거만 바꾼다. 실제 예약 실행의 결과와 콘솔 상태를 확인한다.
5. 독립 검토 후 문서·커밋·정상 push를 완료한다. 별도 새 서버 이관 판을 만들고 해시·복원 확인 후 current 목록을 교체한다. 운영 코드 파일은 현재 서버 판을 읽어 대조한 범위만 반영한다.

세션 인계·인증·실제 원문은 커밋하지 않는다. 운영 DB·다른 프로젝트 예약·서버 재시작은 변경 범위에 포함하지 않는다.
