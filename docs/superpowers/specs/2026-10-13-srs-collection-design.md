# SRS 수집 통합 설계

사용자가 승인한 범위는 ALM-QA-Automation의 SRS 수집·PDF 생성·지식 폴더 배포를 핵심 앱으로 옮기는 것이다. 분석·변경 비교·메일은 기존 QA Agent가 맡는다. ALM 프로젝트의 이슈 Export와 별도 메일은 이식하지 않는다.

ALM의 수집, 본문·이미지 정규화, 고정 문서 분할, HTML 생성과 렌더링 복구를 재사용한다. 코드는 `app/modules/knowledge/srs_crawler/`에 둔다. 인증은 기존 비밀 설정, 문서 구성은 `config/srs-crawler.yaml`, 배포 폴더는 제품 설정에서 읽는다. 다른 저장소를 실행하거나 import하지 않는다.

평일 09:00 PC 작업은 `scripts/collect_srs_spec.py`를 실행한다. 실행 중인 PDF는 날짜별 공개 폴더 밖에 둔다. 수집 건수·문서 배정·PDF 페이지와 배포 위치의 해시·읽기가 모두 정상일 때만 완료 manifest와 날짜별 PDF를 공개한다. 실패하면 기존 지식 파일과 이전 완료본을 유지한다. 중복 실행은 OS 파일 잠금으로 막는다.

배포 준비 폴더는 일반 `mkdir`로 만들어 상위 폴더 권한을 상속한다. 기존 문서는 복구 사본을 먼저 준비한다. 새 파일을 최종 경로에서 읽어 페이지·SHA-256을 검사한 뒤에만 이전 판을 보관한다. 실패 시 원래 파일로 되돌린다. 보관본을 자동 삭제하지 않는다.

09:40 사양서 등록과 10:00 지식 폴더 업로드는 기존 경로를 사용한다. 새 수집기의 실제 실행·배포·서버 읽기를 확인한 후 SRS 수집을 새 PC 작업으로 전환한다. 기존 단일 이슈 분석은 ALM Issue Export를 읽으므로 옛 전체 예약은 이슈 Export 전용으로 바꾼다. 작업 XML과 원본 자료는 보존한다.

실제 문서·인증·예약 XML·실행 자료는 커밋하지 않는다. 새 수집기는 AI와 메일을 호출하지 않는다. 사양 기준은 SPEC REQ-SYNC-003이다.
