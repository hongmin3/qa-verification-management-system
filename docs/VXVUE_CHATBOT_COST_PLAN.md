# VXvue 챗봇 사용량 절감 계획

Opus 모델과 medium 추론을 유지한다. 최신 지침·QA 규칙 전문과 근거를 보존하면서 반복 입력부터 줄인다.

| 순서 | 적용 방안 | 확인 방법 |
|---|---|---|
| 1 | CLI의 실행 경로를 고정하고 공통 지침 뒤에 요청별 자료를 둔다 | 서로 다른 작업의 실행 경로·지침 해시 일치 |
| 2 | 검색마다 전체 문서 목록과 서버 경로를 반복하지 않는다 | 동일 근거·경고·취소선·개정 유지, 전송 문자 수 비교 |
| 3 | 검색·원문·첨부를 묶어 조회하고 충분한 원문은 다시 읽지 않는다 | 묶음 조회와 개별 조회의 근거 일치, 부분 실패 표시 |
| 4 | 대화 JSON 공백을 줄이고 필요한 결과만 답하도록 지침을 보완한다 | 이력·첨부 ID를 손실 없이 복원 |
| 5 | 진행 횟수 제한과 선택 가능한 비용 제한을 둔다 | CLI 명령과 한도 오류 처리, 전체 자동 재시도 없음 |
| 6 | 캐시 쓰기·읽기와 새 입력·출력을 분리해서 기록한다 | 합성 문서 실제 CLI 조회, 사용량 기록 저장 |

대화 이력의 자동 요약은 추가 AI 호출과 QA 조건 누락 가능성이 있어 적용하지 않는다. 답변 캐시는 최신 문서·모델·이력·첨부·소유권에 따라 결과가 달라져 첫 버전에서 사용하지 않는다. 검색 색인과 원본 스냅샷은 기존 로컬 캐시를 사용한다. 로컬 파일 캐시만으로 AI 토큰이 절감됐다고 판단하지 않는다.

검색은 기본 6개 후보, 원문 조회는 기본 4개 구간부터 시작한다. 도구의 `limit`으로 더 넓게 조회할 수 있고, 잘린 원문은 `next_offset`으로 이어 읽는다. 후보가 적다는 이유로 미지원이나 전체 Coverage를 확정하지 않는다.

이미지·PDF는 필요할 때만 원본 페이지를 조회하는 기존 방식을 유지한다. 최대 10개 첨부를 모두 볼 수 있고 긴 결과가 필요한 요청도 수행할 수 있도록 출력 토큰을 일률적으로 낮추지 않는다. 추가 AI 분석·예열 호출·백그라운드 에이전트를 만들지 않는다.

캐시 수명은 CLI 기본 정책을 따른다. 구독 포함 사용량의 주 대화는 1시간, API·사용 크레딧은 5분이 기본이며 강제로 1시간을 쓰면 캐시 쓰기 비용이 높아질 수 있다. 필요하면 `prompt_cache_ttl`을 `5m` 또는 `1h`로 설정한다. [공식 캐시 문서](https://code.claude.com/docs/en/prompt-caching)

`max_turns`는 24회로 설정한다. `max_budget_usd`는 기본 0이며 양수로 설정할 때만 사용한다. 금액 제한은 CLI 추정치 기준이며 실제 청구액과 다를 수 있고 마지막 호출에서 초과할 수 있다. [CLI 제한 옵션](https://code.claude.com/docs/en/cli-reference)

캐시 토큰과 도구 왕복, 전달 문자 수를 따로 비교한다. 캐시 적중률을 구독 사용량 절감률로 환산하지 않는다. 실행 확인 결과와 운영 서버 반영 여부는 `progress.md`에 기록한다.
