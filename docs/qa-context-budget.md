# VXvue·Bellalun 지침과 조회 응답 크기 관리

## 구현 범위와 순서

기존 Redmine 변경은 커밋 `008f34f`를 기준으로 한다. 두 제품은 공통 섹션 ID와 지침 조합 코드를 쓰고 제품별 QA 원문은 분리한다. 기존 전문 조회와 원본 응답은 계속 제공한다.

1. `app/core/qa_workflow.py`에서 표지 짝·허용 ID·의존 섹션을 검사하고 `section`으로 선택한다. `core`는 목차를 포함하며, 선택한 유형의 선행 규칙도 함께 읽는다. 표지가 없는 과거 자료는 전문으로 돌아가 그 사실을 알린다.
2. `desktop.py`와 `bellalun_shared/service.py`의 지침 도구를 같은 조합 함수에 연결한다. 전문 보호 후 잘라서 문자 위치를 유지한다. 기존 호출은 전문을 반환한다.
3. VXvue·Bellalun 검색 결과의 반복 문서 정보는 `documents`에 모은다. 근거·해시·위치·경고·취소선·적용 조건·이어 읽기는 보존한다. `compact=false`는 기존 응답을 제공한다. Bellalun 개별 응답의 반복 지침은 지침 도구로 모은다. 같은 내부 조회기를 쓰는 XIPL은 기존 응답 형식을 유지한다.
4. 큰 원문은 선택 조회를 제공한다. Polarion의 HTML 표시 정보, XLSX 열, 매뉴얼 변경 문단을 선택할 수 있으며 생략 범위와 원본 조회 방법을 알린다.
5. 두 QA 원본을 백업한 뒤 기존 문장·번호·제목을 보존하여 유형별로 배치한다. `mail`도 공통 ID로 둔다. 새 지침은 `meta` 규칙에 따라 관련 주제에 넣고 무손실·표지·크기를 확인한다.
6. Bellalun 서버 배급은 서버 연결 지침과 QA 원문을 사용한다. 로컬 실행·설치·자동 자체검토 참조는 서버 배급에 넣지 않는다. 로컬 참조 파일은 보존한다.

## 호환성과 영향

소비자는 Desktop MCP, 웹 챗봇, 로컬 지식 동기화 예약, Skill ZIP과 기존 설치본이다. 새 선택 입력은 선택 사항이며 과거 호출은 유효하다. 섹션 ID는 `core,spec,tc,issue,doc,verify,release,mail,integ,auto,usage,meta,revlog`다. 개정 이력은 선택 조회에서 자동 포함하지 않는다.

`core` 크기는 VXvue 25,000자·Bellalun 13,000자, 그 밖의 유형은 20,000자를 권고 상한으로 둔다. 기존 내용이 넘으면 경고하고 분할을 제안한다. 상한을 맞추기 위해 근거 규칙을 삭제하거나 자르지 않는다. 설정 파일·인증·예약·제품 원문·과거 검증 결과를 바꾸지 않는다.

## 검증과 게시

`tests/test_qa_workflow_sections.py`는 선택·의존성·잘못된 표지·과거 판·이어 읽기·무손실 실패를 확인한다. 응답 축약과 큰 원문 필터는 실제 도구 경로에서 원본과 대조한다. Bellalun·VXvue Desktop·공통 검색·매뉴얼 회귀, 프로젝트 전체 pytest와 준비 검사를 수행한다. 운영은 이전 파일을 백업하고 바뀐 파일만 반영한 뒤 인증 RPC·해시·health를 재조회한다.
