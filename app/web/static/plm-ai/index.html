PLM에서 실제로 맡길 작업과 결과 예시

PLM은 Teamcenter의 문서번호·첨부·DHF·WBS 작업을 기존 로그인 브라우저와 Computer Use로 수행하는 스킬입니다. 현재 제어 도구와 권한을 확인한 뒤 요청한 일반 저장·연결·완료 처리를 진행합니다. 전자서명·자가결재·최종 승인은 사람이 처리합니다. 사용법 질문에도 교육 근거로 답합니다.

아래 결과는 보고 형식 예시이며 현재 작업의 완료 사실이 아닙니다. 대괄호 안에는 이번 작업에서 확인한 값을 넣습니다. 항목을 펼치면 필요한 입력부터 완료 기준까지 볼 수 있습니다.

1. 프로젝트 산출물 문서번호 등록

PLM 교육 가이드 7장·P7·V01을 작업 요청으로 구성

준비할 입력

  • 프로젝트·폴더·유형·이름·문서 주제·Priority Grade
  • 신규 문서인지 기존 리비전인지·현재 로그인 Teamcenter

복사해서 사용할 요청

PLM 스킬로 로그인된 Edge의 [프로젝트/폴더]에 [문서명]을 프로젝트 산출물로 등록해줘.
문서 주제 [값]과 Priority Grade [값]을 확인하고 문서번호를 발급받아줘.
같은 이름의 기존 문서를 먼저 확인하고, 새 ID·리비전·속성을 다시 열어 보고해줘. Workflow 제출과 승인은 아직 하지 마.

수행할 범위

  1. 서버·프로젝트·폴더·현재 권한·동일 문서 존재 여부를 확인한다.
  2. 유형과 입력값으로 문서를 생성하고 자동 발급된 ID를 확인한다.
  3. 같은 ID를 다시 열어 이름·리비전·주제·Priority Grade와 중복 여부를 읽는다.

결과 보고 형식

문서: [실제 생성 ID / 리비전 / URL]
등록 위치: [프로젝트 / 폴더]
속성: [유형 / 이름 / 주제 / Priority Grade]
재조회: [대조 결과]
미수행: [Workflow 제출·승인]

완료 기준과 제한

  • 예제 DD 번호를 새 업무에 복사하지 않는다.
  • 필수 속성이 불명확하면 현재 화면과 자료로 확인하고, 결과를 바꾸는 값이 남으면 생성 전에 질문한다.
2. PLM 승인 대상 Word 첨부와 체크인

PLM 교육 가이드 8장·P8 기반 예시

준비할 입력

  • 문서 ID·리비전·최종 Word 파일·현재 체크아웃 상태
  • 기존 첨부 교체 여부·문서번호·변경 추적 처리 상태

복사해서 사용할 요청

PLM 스킬로 [문서 ID/리비전]에 첨부 Word를 올리고 필요한 체크인까지 해줘.
기존 첨부가 있으면 먼저 파일명과 교체 범위를 확인해줘. 생성된 PDF에서 문서번호·쪽수·본문을 확인해줘.
전자서명이나 최종 승인은 하지 말고 업로드·체크인·PDF 확인 결과를 구분해 보고해줘.

수행할 범위

  1. 같은 ID·리비전·승인 위치와 기존 첨부를 확인한다. Word의 변경 추적이 남았으면 처리 범위를 확인한다.
  2. 요청 범위에서 파일을 첨부·교체하고 PLM 승인 문서에 필요한 체크아웃·체크인을 수행한다.
  3. PDF가 생성되면 문서번호·쪽수·본문과 첨부·체크인 상태를 같은 객체에서 다시 확인한다.

결과 보고 형식

대상: [ID / 리비전]
파일: [업로드한 파일명 / 보존 또는 교체한 첨부]
체크인: [현재 상태]
PDF: [생성 여부 / 문서번호 / 쪽수 / 확인 범위]
남은 단계: [사용자 검토·서명·승인]

완료 기준과 제한

  • ALM 승인 PDF 첨부와 이 절차를 혼용하지 않는다.
  • 업로드 알림만으로 PDF 생성·승인 완료까지 보고하지 않는다.
3. ALM 승인 PDF 첨부와 Workflow 제출 준비

PLM 교육 가이드 9~10장·P9/P10·V01 기반 예시

준비할 입력

  • ALM 승인 완료 증거·Export PDF·PLM 문서번호·리비전
  • 대상 모델의 승인 위치·선택할 Workflow·사용자 결재 단계

복사해서 사용할 요청

ALM과 PLM 스킬로 [ALM 문서]의 승인 상태와 Export PDF를 확인하고 [PLM 문서 ID/리비전]에 첨부해줘.
문서번호·쪽수·내용을 확인하고 100.Document Approve(ALM)의 타깃과 제출 정보를 확인해 Workflow 제출까지 해줘.
단, 내 전자서명·자가결재가 필요한 시점에는 대상과 다음 버튼을 보여주고 넘겨줘.

수행할 범위

  1. ALM 스킬로 현재 문서의 승인 상태와 Export PDF를 확인한다. 현재 도구에 Export 기능이 없으면 사용자가 제공한 파일과 한계를 확인한다.
  2. PLM의 동일 ID·리비전에 승인 PDF를 첨부하고 문서번호·쪽수·내용을 대조한다. 교육 지침상 ALM 승인 문서에는 PLM 체크아웃·체크인이 필요 없음을 현재 대상과 함께 확인한다.
  3. 정확한 템플릿·타깃·제출 정보를 확인하고 요청·도구 정책이 허용한 제출 단계까지 수행한다. 서명·자가결재는 사용자에게 넘긴다.

결과 보고 형식

ALM: [문서 / 승인 확인 근거 / Export PDF]
PLM: [문서 ID / 리비전 / 첨부 파일 / PDF 대조]
Workflow: [템플릿 / 타깃 / 준비 또는 제출 상태]
사용자 단계: [타스크 / 서명·자가결재가 필요한 다음 동작]

완료 기준과 제한

  • ALM의 미승인 문서를 PLM 자가결재로 대신하지 않는다.
  • V01의 02:10~02:20 사이 승인 클릭은 화면 표본으로 직접 확인한 동작이 아니다.
4. 승인 문서를 DHF Record에 연결

PLM 교육 가이드 12장·P12·V01 04:00~04:27 기반 예시

준비할 입력

  • 상품화 프로젝트·DHF Record·연결할 승인 문서 ID/리비전
  • 현재 Record와 기존 산출물·DHF 개정 필요 여부

복사해서 사용할 요청

PLM 스킬로 [프로젝트]의 DHF에서 [Record 이름/ID]를 찾아 [승인 문서 ID/리비전]을 산출물로 연결해줘.
기존 문서와 승인 상태를 먼저 확인하고, 저장 후 Record Deliverable Relation과 실제 문서 리비전을 재조회해줘.
DHF가 잠겨 있거나 개정이 필요하면 임의로 우회하지 말고 그 지점까지 보고해줘.

수행할 범위

  1. 프로젝트와 맞는 Record·현재 산출물·승인 문서를 확인한다. 이름만 비슷한 다른 Record로 대체하지 않는다.
  2. 권한·상태가 허용되면 산출물 첨부로 지정 문서를 연결한다.
  3. Record를 다시 열고 LATEST RECORDS의 관계 열과 실제 문서 ID·리비전을 확인한다.

결과 보고 형식

프로젝트·Record: [이름 / 실제 ID]
연결: [Record → 승인 문서 ID/리비전]
재조회: [Record Deliverable Relation / 문서 승인 상태]
미완료: [잠금·연구소 개정·권한 제한]

완료 기준과 제한

  • 모델별 DHF 적용 표와 미확정 대상을 먼저 확인한다.
  • 관계 표시만 보고 다른 리비전·미승인 문서를 올바른 연결이라고 처리하지 않는다.
5. 문서 개정과 DHF의 새 리비전 연결

PLM 교육 가이드 11·13장과 P11·P13/P14 기반 예시

준비할 입력

  • 기존 문서 ID·리비전·개정 사유·새 파일
  • 문서 종류·버전·DHF Recordset/Record·기존 연결의 처리 범위

복사해서 사용할 요청

PLM 스킬로 [문서 ID/현재 리비전]의 [개정 사유]를 확인해 새 리비전을 준비해줘.
새 파일 첨부와 재조회까지 진행하고, 승인 뒤 연결할 DHF Record와 기존 리비전 처리 대상을 정리해줘.
이번 요청에 없는 기존 승인 문서 삭제나 최종 승인은 하지 마.

수행할 범위

  1. TC 리비전과 Plan/Report의 버전별 새 문서번호 규칙을 구분하고 현재 대상의 개정 방식을 확인한다.
  2. 허용된 개정·파일 교체·체크인 또는 ALM PDF 첨부를 수행하고 이전/새 리비전을 대조한다.
  3. DHF 승인 완료로 수정할 수 없으면 연구소 리비전 필요를 보고한다. 승인 전의 새 문서를 승인 완료 산출물처럼 연결하지 않는다.

결과 보고 형식

문서 개정: [ID / 이전 리비전 / 새 리비전]
파일·상태: [새 첨부 / 체크인 또는 PDF / 승인 전 상태]
DHF: [현재 연결 / 승인 뒤 갱신할 Record / 개정 필요 여부]
미수행: [서명·승인·요청하지 않은 삭제]

완료 기준과 제한

  • 승인 완료 DHF의 변경 제한을 우회하지 않는다.
  • 이전 문서를 잘라내는 작업은 대상과 영향이 확인된 구체적인 요청 범위에서만 진행한다.
  • 준비 요청에 파일 첨부·저장·재조회가 함께 지정돼 있으면 그 단계까지 수행한다. 최종 승인이나 요청하지 않은 DHF 교체는 추가하지 않는다.
6. TC 저장 위치를 등록하고 파일은 첨부하지 않기

PLM 교육 가이드 15장·P19 기반 예시

준비할 입력

  • TC 문서번호 또는 신규 대상·리비전·실제 서버 저장 경로
  • 대상 프로젝트·문서 속성 필드·현재 TC 승인/연결 상태

복사해서 사용할 요청

PLM 스킬로 [TC 문서 ID/리비전]의 저장 위치 속성에 [실제 서버 경로]를 입력해줘.
이 TC는 교육 지침의 변경 절차에 따라 파일을 첨부하지 않는 대상인지 확인해줘.
저장 후 같은 ID에서 경로와 기존 첨부 상태를 재조회하고, 자가승인과 DHF는 다음 단계로 구분해줘.

수행할 범위

  1. 현재 대상이 TC인지·신규 문서번호/리비전 방식과 실제 경로를 확인한다.
  2. 현재 화면의 올바른 속성에 요청 경로를 저장한다.
  3. 같은 ID·리비전의 속성과 첨부·승인·DHF 현재 상태를 다시 읽는다.

결과 보고 형식

TC 문서: [ID / 리비전]
저장 위치: [기존 값 / 저장된 경로]
첨부: [현재 첨부 상태 / 이번 파일 미첨부]
다음 단계: [사용자 자가승인 / DHF 연결 요청 여부]

완료 기준과 제한

  • 경로 문자열 저장과 실제 서버 파일 존재·접근 검증을 구분한다.
  • 모든 PLM 문서에 파일 미첨부 규칙을 적용하지 않는다.
7. WBS 작업 내용·레퍼런스 등록과 일반 완료

PLM 교육 가이드 14장·P15~P18을 작업 요청으로 구성

준비할 입력

  • 프로젝트·타스크 ID·담당자·실제 완료한 작업 내용
  • 승인된 레퍼런스/VCN·완료 조건·현재 타스크 상태

복사해서 사용할 요청

PLM 스킬로 [프로젝트/타스크 ID]의 현재 담당자와 완료 조건을 확인해줘.
내가 제공한 작업 내용 [내용]과 승인 레퍼런스 [ID]를 저장하고, 일반 완료 동작이면 완료 처리까지 해줘.
전자서명·결재가 요구되거나 산출물이 부족하면 그 지점에서 멈춰줘. 저장 뒤 같은 타스크의 내용·관계·상태를 다시 읽어줘.

수행할 범위

  1. 타스크·담당자·대상 모델·선행 산출물·현재 상태를 확인한다. 매핑/할당 시점이 불명확하면 가이드 17장 확인 필요 항목을 적용한다.
  2. 요청한 작업 내용과 승인 레퍼런스를 저장한다.
  3. 서명·결재를 요구하지 않고 선행 조건이 확인된 일반 완료만 요청 범위에서 실행한다.
  4. 같은 타스크의 내용·레퍼런스·완료 상태를 다시 조회하거나, 사용자에게 넘긴 단계와 미완료 이유를 보고한다.

결과 보고 형식

타스크: [ID / 담당자 / 프로젝트]
저장 내용: [작업 내용 / 레퍼런스 ID]
상태: [변경 전 / 재조회한 상태]
완료 또는 보류 근거: [충족한 조건 / 부족한 산출물 / 사용자 서명 단계]

완료 기준과 제한

  • 작업 내용 저장과 WBS 완료는 별도 결과다. 수행하지 않은 업무를 완료로 만들지 않는다.
  • 타스크가 오지 않았다는 이유로 다른 타스크나 프로젝트에서 대신 완료하지 않는다.

Codex와 Claude Code에 설치하기

Python 3을 실행할 수 있는 PC와 QA 서버에 접속할 수 있는 사내망이 필요합니다. PLM 계정·비밀번호·토큰을 이 스킬에 입력하지 않습니다.

  1. 준비 사항을 확인합니다.

    Windows PowerShell에서 py --version을 실행해 Python 3이 있는지 확인합니다. 다른 운영체제에서는 python3 --version을 사용합니다.

  2. 위의 PLM 스킬 ZIP을 받고 압축을 풉니다.

    압축 안의 plm 폴더 전체를 사용합니다. SKILL.md, scripts, server.json을 함께 둡니다.

  3. 사용하는 도구의 사용자 스킬 폴더에 넣습니다.
    사용 도구Windows에서 둘 위치
    Codex%USERPROFILE%\.codex\skills\plm
    Claude Code%USERPROFILE%\.claude\skills\plm

    macOS·Linux에서는 홈 폴더 아래 ~/.codex/skills/plm 또는 ~/.claude/skills/plm을 사용합니다. 같은 이름의 사용자 수정본이 있으면 먼저 보관하고 내용을 비교합니다.

  4. 새 대화에서 첫 질문을 합니다.

    PLM 스킬로 로그인된 Edge의 [문서 ID/리비전]에 [승인 PDF]를 첨부하고 문서번호·쪽수·저장 상태를 재조회해줘. 전자서명·승인은 하지 마.

    가이드의 절차와 함께 P7 같은 원본 슬라이드나 영상 시점이 제시되는지 확인합니다. Codex에서는 $plm으로도 부를 수 있습니다.

서버 자료를 읽는지 직접 확인하기

Codex 사용자 폴더에 설치했다면 PowerShell에서 실행합니다. Claude Code만 사용한다면 경로의 .codex를 .claude로 바꿉니다.

py -X utf8 "$env:USERPROFILE\.codex\skills\plm\scripts\knowledge.py" status

metadata_verified: true와 자료 판·가이드 장수 등이 나오면 자료 목록과 본문 파일의 해시 대조가 끝난 것입니다. 실제 PLM에서 시험이나 승인을 실행한 결과는 아닙니다.

위 폴더 설치는 로컬 Python을 사용하는 Codex·Claude Code용입니다. Claude Desktop·Cowork의 Skill ZIP 업로드와 실행 조건은 아래에서 따로 설명합니다. 브라우저의 상세 가이드와 영상은 별도 스킬 설치 없이 사용할 수 있습니다.

Claude Code와 Claude Desktop·Cowork에서 사용하기

Claude Code

  1. 현재 PLM ZIP의 plm 폴더 전체를 ~/.claude/skills/plm에 둡니다. Windows에서는 %USERPROFILE%\.claude\skills\plm입니다. 기존 사용자 수정본이나 다른 스킬로 연결된 폴더는 먼저 비교·보관합니다.
  2. Claude Code에서 /plm으로 호출하거나 “PLM 스킬로 로그인된 브라우저의 [대상]을 처리하고 저장 결과를 다시 확인해줘”라고 요청합니다. 스킬 목록이 갱신되지 않았다면 새 세션에서 확인합니다.
  3. Python 3과 QA 서버에 닿는 사내망에서 아래 명령을 실행해 자료 판과 metadata_verified를 확인합니다. 실제 브라우저 작업은 현재 Computer Use 도구와 대상 권한을 별도로 확인합니다.
py -X utf8 "$env:USERPROFILE\.claude\skills\plm\scripts\knowledge.py" status

Claude Code 공식 스킬 안내

Claude Desktop·Cowork

  1. 사용 중인 Claude에서 Skills 및 코드 실행·파일 생성이 허용돼 있는지 확인합니다. 조직 계정은 관리 정책에 따라 표시가 다를 수 있습니다.
  2. Customize → Skills → + → Create skill → Upload a skill에서 위의 PLM ZIP을 업로드하고 스킬을 켭니다. 이것은 Skill 업로드이며 MCP 확장 설치가 아닙니다.
  3. 현재 세션에 로컬 브라우저·컴퓨터 제어 도구가 연결돼 있는지, 실제 실행 위치에서 사내 QA 서버와 대상 ALM·PLM에 접근할 수 있는지 확인합니다. 같은 이름의 스킬을 올렸다는 이유만으로 로컬 PC 연결이 생기지는 않습니다.

일반 채팅의 클라우드 실행 환경은 PC의 로그인 탭이나 사내망에 직접 닿지 않을 수 있습니다. 그런 환경에서는 실제 등록·수정이 가능한 것으로 표시하지 않고, 접근 가능한 설명·검토·준비 범위로 보고합니다. Cowork에서도 현재 Computer Use 연결·권한·서버 접근을 확인한 뒤 실제 작업을 진행합니다.

Claude 공식 Skill 업로드 안내

공식 설치 절차를 확인해 작성했습니다. 이번 검증은 Claude Code의 로컬 설치 경로·자료 조회까지이며, Claude Desktop·Cowork의 사용자 계정 업로드와 실제 브라우저 쓰기는 별도로 확인해야 합니다.

ALM과 제품 스킬을 함께 사용하기

ALM 스킬은 문서 서명·승인 상태·PDF Export와 TC·Test Run을 담당합니다. PLM 스킬은 Teamcenter 문서번호·첨부·DHF 연결·WBS를 안내합니다. VXvue·Bellalun 스킬은 제품 사양·기존 TC·실제 시험 근거를 확인합니다.

예: “ALM과 PLM 스킬로 승인 PDF를 등록하는 순서를 확인하고, VXvue 제품 스킬로 Plan·Report에 필요한 근거를 찾아줘.” 기존 ALM 설치본과 연결 설정을 바꾸지 않습니다.

ALM 스킬 사용 안내

로그인된 Edge·Chrome에서 실제 작업하기

구체적인 등록·수정·첨부·DHF 연결 요청에는 현재 Computer Use 도구와 기존 로그인된 Edge·Chrome을 사용합니다. 먼저 Teamcenter 서버·프로젝트·문서 ID·리비전·상태를 확인합니다.

  1. 대상 모델의 승인 위치와 DHF 여부, 문서 주제·Priority Grade·첨부 파일을 확인합니다.
  2. 요청한 문서번호 등록·일반 속성 저장·파일 첨부·DHF 연결을 수행합니다.
  3. 같은 ID와 리비전을 다시 열어 저장 결과와 Record Deliverable Relation을 확인합니다.
  4. 변경 전후·재조회 결과·미수행 범위를 보고합니다.

전자서명·자가승인·최종 승인은 사용자가 직접 합니다. WBS의 일반 완료는 구체적인 요청과 선행 산출물을 확인한 범위에서 수행하고 같은 타스크를 재조회합니다. 서명·결재가 필요하면 사용자에게 넘깁니다. 자료 조사와 준비만 요청하면 Teamcenter 기록을 바꾸지 않습니다. 이미 요청한 일반 저장마다 허락을 반복해서 묻지 않으며 현재 도구의 확인 정책을 따릅니다.

현재 운영 Teamcenter에서 등록·승인·DHF 변경을 직접 시험하지 않았습니다. 브라우저 연결이나 대상 식별이 불확실하면 입력을 중단하고, 새 프로필로 바꾸거나 로그인 정보를 추출하지 않습니다.

설명과 근거를 물어볼 때

아래 답변 요점은 서버 가이드에서 확인한 사례입니다. 현재 운영 설정과 제품 시험 결과는 별도로 확인합니다.

PLM 스킬로 ALM 승인 PDF를 올릴 때 체크아웃·체크인이 필요한지 알려줘.

ALM 승인 문서는 PLM 체크아웃·체크인을 하지 않는 교육 절차입니다. 먼저 ALM 승인과 PDF Export를 확인합니다.

자료를 사용할 때 알아둘 점

  • 교육 자료와 현재 Teamcenter 설정은 다를 수 있습니다. 문서 유형·상태·템플릿·권한을 현재 대상에서 확인합니다.
  • 영상은 10초 간격과 끝부분 화면 표본 28개를 대조했습니다. 음성 전체 전사와 표본 사이 모든 클릭 확인은 포함하지 않았습니다.
  • 사용자 가이드 v0.1 및 기본기능·문서관리 교육자료 PPT 2개는 미포함입니다. 확보되면 다음 자료 판에 추가합니다.
  • Setup·상품화 과제 범위와 WBS 배정·완료 의미의 미확정 항목은 가이드 17장에서 확인합니다.
  • 서버 조회 도구는 읽기 전용입니다. 해시 불일치에는 조회를 중단하고 오래된 로컬 자료로 대신하지 않습니다.
