Bellalun AI 설치·사용 가이드

Bellalun Viewer의 사양서·매뉴얼·기존 TC와 최신 통합 QA 지침을 QA 서버에서 찾아 근거와 함께 답합니다. 개인 PC에 지식파일을 복사할 필요 없이 사내 파트원이 같은 자료 판을 사용합니다.

연결 프로그램의 표시 이름은 VXvue AI입니다. 이 연결에 Bellalun 전용 도구를 함께 제공합니다. Bellalun 질문에는 bellalun_ 도구와 Bellalun QA 지침을 사용합니다.

설치 · 첫 질문 · 상세 업무 사례 · 기본 질문 · 최신화 · 지원 범위 · 문제 해결

1. 연결과 Skill 설치

Claude Desktop

  1. 이미 VXvue AI 확장을 사용한다면 확장을 껐다 켜고 새 대화를 엽니다. 신규 사용자는 공용 서버 확장(.mcpb)을 직접 받습니다. PC 등록 번호가 있으므로 받은 파일을 다른 사람에게 전달하지 않습니다.
  2. Claude Desktop의 설정 → 확장 프로그램 → 고급 설정 → 확장 프로그램 설치에서 받은 파일을 설치합니다. 자세한 화면 순서는 연결 설치 안내에 있습니다.
  3. Bellalun 서버 Skill ZIP을 받아 사용자 지정(Customize) → Skills → + → 스킬 만들기 → 스킬 업로드에서 등록하고 켭니다.

Claude Code

기존 공용 연결 설치 안내의 PowerShell 명령으로 사용자 범위 연결을 설치합니다. 서버 주소나 키를 수동 복사하지 않습니다. 위 Skill ZIP의 bellalun-server-ai 폴더를 ~/.claude/skills/ 아래에 풀고 Claude Code를 새로 시작합니다.

Codex

기존에 연결한 VXvue AI (QA 서버) 플러그인을 활성화하고 연결을 다시 불러옵니다. 위 ZIP의 bellalun-server-ai 폴더를 사용자 스킬 위치인 ~/.agents/skills/ 아래에 풀고 새 작업에서 $bellalun-server-ai를 호출합니다. 기존 설치가 ~/.codex/skills/를 사용하는 환경은 그 위치를 유지할 수 있습니다. 서버 연결이 아직 없다면 관리자가 제공하는 기존 QA 서버 연결을 먼저 설치해야 합니다. Skill ZIP만으로 서버 연결이 생기지는 않습니다. 공식 Skill 설치 위치 안내도 참고하세요.

기존 로컬 bellalun-ai·bellalun-local-knowledge는 보존됩니다. 서버에서 조사할 때는 bellalun-server-ai를 선택합니다.

2. 첫 질문과 확인할 결과

Bellalun 서버 스킬로 현재 자료 목록과 최신 QA 지침을 확인해줘.
bellalun_get_status와 bellalun_get_workflow를 사용하고 지침은 끝까지 읽어줘.

정상 연결이면 Bellalun 문서 목록·해시·bellalun-으로 시작하는 자료 판과 추출 한계가 확인됩니다. 다음 질문은 같은 판에서 검색하고 원문을 읽습니다. 원문 파일명과 페이지 또는 시트·행을 답에 남겨야 합니다.

이전에 맡겼던 Bellalun 업무를 다시 요청하는 방법

아래는 과거 Bellalun 요청을 바탕으로 다시 구성한 업무 예시입니다. 과거 검토 결론을 현재 제품 판정으로 가져오지 않고 최신 Bellalun 자료 판·지침과 이번 증거를 다시 읽습니다. 공용 Bellalun 도구는 읽기 전용이며 Viewer·장비 제어·실시간 Redmine 수정·메일 발송 기능을 제공하지 않습니다. 별도 로컬 파일 도구가 있는 경우의 산출물 생성과 제품 시험은 구분합니다.

아래 결과는 보고 형식 예시이며 현재 작업의 완료 사실이 아닙니다. 대괄호 안에는 이번 작업에서 확인한 값을 넣습니다. 항목을 펼치면 필요한 입력부터 완료 기준까지 볼 수 있습니다.

1. Crop 영상과 Image Processing의 전체 영역 표시 판단

과거 114T1 Spot Paddle·Masking Area·Crop 문의 재구성

준비할 입력

  • 현재 Viewer/펌웨어 버전·Paddle·Masking 설정·신규/과거 영상 구분
  • View·Image Processing의 캡처/영상·로그·Apply 수행 여부

복사해서 사용할 요청

Bellalun 스킬로 첨부한 View의 Crop 영상과 Image Processing 전체 영역 표시를 최신 사양·매뉴얼과 대조해줘.
과거 114T1 검토처럼 Masking Yes/No·사용자 Crop·신규/과거 영상·Apply 전후를 구분해줘.
문서상 Expected·실제 관찰·사양 문의·확정 가능한 결함·추가 확인을 나눠줘. Apply를 하지 않았다면 이후 상태를 추정하지 마.

수행할 범위

  1. Bellalun 상태와 workflow를 끝까지 읽고 이번 버전·관찰 조건·증거를 확인한다.
  2. 현재 Crop/Image Processing 사양과 앞뒤 조건을 찾아 원문을 읽고 실제 화면·로그의 시점과 대응시킨다.
  3. 과거 SRS 문구와 이번 판의 동작을 구분해 정상·정책 확인·결함 후보를 근거별로 정리한다.

결과 보고 형식

조건: [버전 / Paddle·Masking / 신규·과거 / Apply 여부]
Expected: [현재 원문 / 문서·위치]
Actual: [View / Image Processing / 로그 시점]
판단: [사양 일치·문의·결함 후보 / 근거]
미확인: [Apply 후 상태 / 추가 촬영·저장 확인]

완료 기준과 제한

  • 전체 영역 표시만으로 Masking 유지/해제 결함을 단정하지 않는다.
  • 과거 사양과 일치했던 관찰을 지금도 정상이라는 현재 판정으로 사용하지 않는다.
2. 촬영 View·Send Preview·실제 수신 DICOM 비교

과거 114T1 DICOM Send 영향 검토 요청 재구성

준비할 입력

  • Storage 설정·SW Collimation·Apply Preview Position·Preview 저장/미진입 상태
  • 원본·Preview 캡처·실제 수신 DICOM·Tag·수신 시스템 정보

복사해서 사용할 요청

Bellalun 스킬로 첨부한 촬영 View, Send Preview, 실제 수신 DICOM을 각각 비교해줘.
Rows/Columns·영상 위치·잘림·Laterality·View Position과 None/Cut/Fill 설정을 확인해줘.
Preview와 수신 영상을 같은 결과로 취급하지 말고, DICOM 파일이 없으면 수신 결과는 미확인으로 남겨줘.

수행할 범위

  1. Storage별 전송 설정과 Preview 저장·진입 여부, 각 파일의 동일 시험 대응을 확인한다.
  2. 현재 사양의 None/Cut/Fill·Preview 위치 적용 조건을 읽고 각 화면 및 DICOM Tag·픽셀 영역을 비교한다.
  3. 제공된 증거에서 확인한 차이와 재전송·수신 측 확인이 필요한 항목을 분리한다.

결과 보고 형식

시험 대응: [영상 식별자 / Storage / 설정 / 증거 파일]
비교표: [View / Preview / 수신 DICOM의 크기·위치·잘림·Tag]
판단: [조건별 기대 / 실제 차이 / 근거]
추가 확인: [미제공 DICOM / 수신 측 표시 / 재시험]

완료 기준과 제한

  • 뷰어 화면·Preview 캡처만으로 실제 수신 DICOM을 검증했다고 하지 않는다.
  • 과거 3072×2304·1152×1152 같은 값은 이번 파일의 측정값으로 다시 확인한다.
3. 기존 TC를 유지하며 패치 검증 범위 보강

과거 114T1 TC 고도화 요청 재구성

준비할 입력

  • 최신 TC 원본·변경사항·대상 버전·기존 결과 이력
  • 현재 사양·실제 시험 환경·추가 입력 데이터

복사해서 사용할 요청

Bellalun 스킬로 [패치 변경사항]을 기존 TC와 대조하고 누락 조건을 보강해줘.
기존 목적·순서·이력을 지키고 SRS No | 변경사항 | 변경사항 상세 | Title | Precondition | Test Step | Expected Result | Test Data 형식으로 정리해줘.
Precondition에는 실제 환경만 두고 Viewer 설정과 조작은 Step에 써줘. 사양 충돌 후보는 TC에 확정값으로 섞지 말고 별도 목록으로 줘.

수행할 범위

  1. 최신 원본과 현재 자료 판에서 변경 조건·기존 TC·Step/Expected를 대조한다.
  2. 유지·최소 수정·누락 보강·사양 문의를 분리하고 적용 범위를 확인한다.
  3. 파일 작성이 요청되고 로컬 파일 도구가 있으면 별도 산출물을 저장·재조회해 열·행·번호·원본 이력 보존을 확인한다. 서버 조회만 있으면 교정안 표를 제공한다.

결과 보고 형식

원본: [파일·해시 / 시트·행 / 대상 버전]
TC 대조: [기존 ID / 유지·수정·추가 / 사양 근거]
작성안: [8개 열 / Step·Expected 대응]
별도 확인: [사양 충돌·질문·실제 시험 미수행]
저장 검증: [산출물 위치 / 다시 읽은 행·열 / 원본 보존]

완료 기준과 제한

  • 과거 43 TC·21 확인항목을 이번 산출물 개수로 사용하지 않는다.
  • 불필요한 Test Data를 채우거나 과거 Pass를 보강 TC의 통과 결과로 복사하지 않는다.
4. 패치 전 증거와 복구 준비 체크리스트

과거 114T1 패치 전 준비 목록 요청 재구성

준비할 입력

  • 대상 PC·현재/대상 버전·패치 절차·복구 계획
  • 기존 설정·영상·Preview 위치·QC·수신 DICOM·로그 확보 상태

복사해서 사용할 요청

Bellalun 스킬로 [대상 패치] 전에 남겨야 할 증거와 복구 준비를 체크리스트로 정리해줘.
설정·영상·Preview 위치·수신 DICOM·QC 결과와 로그를 분리해줘.
이번에는 패치 적용·삭제·설정 변경을 하지 말고, 내가 제공한 증거가 있는 항목만 확보로 표시해줘.

수행할 범위

  1. 현재 패치 범위와 영향을 사양·기존 TC·지침으로 확인한다.
  2. 변경 전/후 비교 대상과 보관 위치·복구 자료·담당자를 목록화한다.
  3. 제공된 파일과 확인 근거가 있는 항목만 확보로 표시하고 나머지는 미확보·확인 필요로 둔다.

결과 보고 형식

준비 목록: [항목 / 이유 / 변경 전 증거 / 보관 위치 / 상태]
우선 보존: [설정·영상·Preview·DICOM·QC·로그]
복구: [절차·자료·확인 주체]
미수행: [패치 적용 / 삭제 / 설정 변경 / 복구 실행]

완료 기준과 제한

  • 준비 목록 작성은 캡처·백업·실제 패치·복구 성공의 증거가 아니다.
  • 원본 영상과 설정은 요청 없이 수정하거나 지우지 않는다.
5. 관찰과 Expected를 구분한 Issue 초안

과거 Crop·Send 및 화면 문의의 이슈 초안 요청 재구성

준비할 입력

  • 재현 단계·Actual 캡처·로그·버전·발생 조건
  • 관련 Issue 본문/댓글·현재 Expected 근거

복사해서 사용할 요청

Bellalun 스킬로 첨부 캡처와 로그를 보고 이슈 초안을 작성해줘.
실제 확인한 현상·문서상 Expected·추정 원인·미확인을 구분하고, 결함인지 정책 확인이 필요한지 먼저 판단해줘.
서버에서 직접 읽지 못하는 관련 Redmine은 제공한 본문만 쓰고 실시간 전체 조회나 등록 완료로 쓰지 마.

수행할 범위

  1. 제공된 현상과 재현 절차·시점을 읽고 현재 문서의 관련 조건을 찾는다.
  2. 정상/사양 문의/결함 후보를 구분하고 필요한 추가 증거를 제시한다.
  3. 제목·환경·Step·Expected·Actual·첨부·관련 항목·미확인을 초안으로 작성한다.

결과 보고 형식

판단: [사양 문의 / 결함 후보 / 추가 확인]
제목: [관찰 중심 제목]
환경·재현: [버전·조건 / 실제 수행 단계]
Expected / Actual: [원문 근거 / 제공된 관찰]
첨부·관련 항목: [확인한 자료 / 미조회 범위]
상태: [초안 / 서버 등록 미수행]

완료 기준과 제한

  • Bellalun 서버 도구에는 실시간 Redmine 쓰기 기능이 없다.
  • 추가 브라우저 등록을 요청받으면 ALM 등 해당 시스템 스킬·기존 로그인 연결·프로젝트 권한을 별도로 확인한다.
6. DICOM Send 범위의 검증결과 공유 메일 초안

과거 114T1 검증 진행 결과·이슈 공유 메일 요청 재구성

준비할 입력

  • 이번 Viewer/펌웨어 버전·실제 기간·검증 범위·결과·이슈 목록
  • 메일에 제외할 범위·참고 전용 파일·수신자/발송 요청 여부

복사해서 사용할 요청

Bellalun 스킬로 제공한 이번 검증 결과만 사용해 메일 초안을 작성해줘.
과거 114T1 메일처럼 확인 버전 → 기간 → 검증 범위 → 결과 → 이슈 현황 → 후속 계획 순서로 정리해줘.
이번 범위는 DICOM Send이고 Export / Print는 협의된 제외 항목이야. 참고 TC 파일은 메일에 언급하지 마.
이슈 표는 번호 | 등급 | 제목으로 쓰고 최종 적합/부적합은 비워 둬. 초안만 만들고 발송하지 마.

수행할 범위

  1. 제공된 실제 결과와 이전 메일의 인용/첨부 범위를 확인하고 이번 버전·기간·대상·제외를 정리한다.
  2. 현재 결과에 근거한 수량·이슈 등급·미완료를 표로 구성한다. 근거 없는 기간·결과·판정은 채우지 않는다.
  3. 한국어 메일 초안과 필요한 경우 Outlook 붙여넣기용 산출물을 준비한다. 별도 도구가 실제 클립보드를 썼으면 그 범위만 검증한다.

  • 과거 이슈 7건·등급 B 1/C 6을 이번 결과에 복사하지 않는다.
  • 초안·파일·클립보드 확인은 메일 전송·수신 확인이 아니다.
7. 매뉴얼 개정·번역을 사양과 대조하고 코멘트 준비

과거 Bellalun 매뉴얼·현지화 검토 요청 재구성

준비할 입력

  • 원본/개정 매뉴얼·언어·대상 버전·검토할 절
  • 관련 사양·실제 화면 명칭·출력 페이지 기준

복사해서 사용할 요청

Bellalun 스킬로 첨부 매뉴얼의 개정 문구와 관련 사양·실제 UI 용어를 대조해줘.

번역 표현의 어색함과 기능 설명 오류를 구분하고, DOCX 문단 번호를 출력 쪽수처럼 쓰지 마.

수행할 범위

  1. 현재 판·언어·변경 범위와 문서 위치 기준을 확인한다.
  2. 관련 사양·매뉴얼과 실제로 제공된 UI 증거를 대조한다.
  3. 기능 오류·용어 불일치·번역 개선·확인 필요를 나눠 문서 순서로 코멘트를 정리한다.

  • 코멘트 초안 작성과 원본 수정·ALM 저장·제품 실행 검증은 별도 단계다.

3. 업무별 요청 예시

업무복사해서 사용할 질문
사양 확인Crop과 Image Processing의 적용 범위를 사양서·매뉴얼에서 찾아줘. 촬영 UI, Send Preview, 수신 DICOM의 근거를 구분해줘.
기존 TC 검토이 변경사항을 기존 TC가 검출할 수 있는지 Step·Expected로 대조하고, 누락 후보와 근거를 보여줘.
이슈 초안첨부 캡처·로그에서 확인한 Actual과 문서상 Expected를 구분해 이슈 초안을 작성해줘. 조회하지 못한 관련 이슈는 미확인으로 표시해줘.
매뉴얼 대조첨부한 매뉴얼 개정 내용을 관련 사양과 대조해줘. 원문 문구, 한국어 설명, 판단 근거, 수정 제안을 구분해줘.
검증 결과 메일제공한 수행 결과만으로 통합 QA 지침 양식의 메일 초안을 작성해줘. 날짜·횟수·적합 판정은 내가 준 값만 사용해줘.

4. 최신 지침과 자료 동기화

담당자가 공통 Skill과 지식 폴더를 서버에 동기화하면 모든 사용자의 다음 상태·지침 조회에 새 자료 판이 반영됩니다. QA 규칙 변경 때마다 Skill ZIP을 다시 설치할 필요는 없습니다. 진행 중인 조회는 이미 받은 판을 유지하며 서버 재시작 후에는 상태부터 다시 확인합니다.

공통 QA 지침은 통합본 하나를 사용합니다. 서버의 원본 해시와 담당자 원본을 비교해 동기화 여부를 확인합니다. 운영자가 쓰는 동기화 절차는 Bellalun 자료 현황에서 결과를 확인합니다.

담당자 PC의 별도 Bellalun 동기화는 매일 10:10과 로그인 때 실행합니다. 실패하면 15분 간격으로 3회 재시도합니다. 담당자 PC가 로그인되어 있어야 하며, 공통 원본 변경이 서버에 반영되는 시각은 마지막 성공한 동기화를 기준으로 확인합니다.

5. 지원 범위와 확인이 필요한 부분

  • 실제 Viewer 실행·장비 제어·수신 DICOM 검증 결과를 대신 만들지 않습니다. 문서상 Expected와 실제 관찰은 따로 판단합니다.
  • 이 서버의 Bellalun 도구에는 실시간 Redmine 조회·이슈 수정·메일 발송·공통 Skill 수정 기능이 없습니다. 관련 이슈 본문과 로그는 제공한 자료로 검토합니다.
  • DOCX는 문단·표 위치로 인용하며 Word 출력 페이지·변경 추적·메모의 모든 표시를 보장하지 않습니다. PDF 그림·표는 원본 페이지 이미지를 직접 확인합니다.
  • 검색 결과가 없거나 텍스트가 적다는 이유만으로 기능 미지원이나 사양 부재를 확정하지 않습니다.
  • 기존 사내 접속·PC별 등록·회수 정책이 적용됩니다. 외부 인터넷에 제품 자료를 공개하는 서비스가 아닙니다.

6. 연결이 안 될 때

  1. 사내망에서 이 안내와 서버 상태가 열리는지 확인합니다.
  2. 연결을 다시 시작하고 새 대화에서 bellalun_get_status를 요청합니다. 도구가 계속 안 보이면 이 화면의 최신 확장을 다시 받아 설치합니다.
  3. PC 등록이 만료되거나 회수됐다면 각자 설치 파일을 새로 받습니다. 다른 PC의 키나 파일을 복사하지 않습니다.
  4. 자료 누락·해시 불일치·지침 오류는 운영 담당자에게 도구명·오류·자료 판만 전달합니다. 키·설정 파일 전체는 보내지 않습니다.
  5. 서버 조회가 실패한 상태를 자료 확인 완료로 표시하지 않고, 로컬 자료로 바꾸기 전에 조회 대상을 다시 정합니다.
