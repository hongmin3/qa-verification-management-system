이런 일을 맡길 수 있어요 (실제 요청 사례)

Claude Code·Codex에서 실제로 맡겼던 요청을 업무별로 정리했습니다. 대괄호 부분만 바꿔서 그대로 쓰면 됩니다. 오른쪽 칸은 그 일을 하려면 무엇이 준비돼 있어야 하는지 알려 줍니다.

하고 싶은 일이렇게 요청했어요필요한 것
연결이 빠진 SRS 찾기“ALM 스킬로 SRS STC Coverage에서 사양 설명은 있는데 TC가 하나도 verified 되지 않은 SRS가 뭐가 있는지 조사해줘.”개인 PAT
기존 TC로 연결할 수 있는지 조사“Main TC를 전수조사해서 STC 연결이 없는 SRS 중 기존 TC로 연결할 수 있는 게 있는지 찾아줘. 일단 조사만 해줘.”개인 PAT, VXvue 스킬
보강안 확인 후 반영“보강이 필요한 TC는 각각 어떻게 바꿀지 먼저 보여줘. 내가 승인하면 ALM에 올리고 SRS 연결과 문서 최신화까지 해줘.”개인 PAT, 로그인된 브라우저
Checklist TC를 ALM TC로 등록“Basic Checklist [번호]번 TC를 ALM TC Work Item으로 올리고 Basic Function Test Case 문서에도 넣어줘.”로그인된 브라우저(문서 편입), 개인 PAT
엑셀 기준으로 신규 TC 한꺼번에 등록“내가 고친 엑셀 기준으로 신규 TC를 전부 ALM에 올리고, TC 문서 반영·SRS 링크·[Test Run]에 추가까지 해줘. 보류 이슈가 Fail로 안 돼 있으면 Fail 처리하고 이슈와 링크해줘.”개인 PAT, 로그인된 브라우저
TC와 SRS 관계 수천 건 일괄 연결“원본 엑셀과 ALM의 TC ID·제목·SRS 번호가 일치하는 TC에 verifies 관계를 일괄 반영해줘.”개인 PAT, 사내망 PC
등록된 TC 속성 일괄 수정“Main TC에 반영된 Checklist TC는 STC Category에 Full Function을 추가하고, Function과 TC위치를 Main TC 기준으로 맞춰줘.”개인 PAT
ALM에서 직접 고친 내용 되가져오기“내가 ALM에서 [VP 번호] 내용을 조금 고쳤어. 바뀐 내용을 서버와 내 PC의 TestCase 엑셀에도 맞춰줘.”개인 PAT, VXvue 스킬
이슈 완료 처리와 댓글“[VP 번호] 완료 처리해줘. 게시할 댓글과 바꿀 필드를 먼저 보여주고, 내가 확인하면 올린 뒤 다시 읽어서 알려줘.”개인 PAT
검증 메일에 ALM 이슈 넣기“검증완료 메일 초안을 쓰고 이슈 목록에 ALM 이슈 [VP 번호]도 넣어줘.”개인 PAT(읽기), 제품 스킬
교육 자료에서 근거 찾기“ALM 교육자료에서 Roundtrip 설명이 있는 장 번호와 자료 판만 알려줘. 파일은 수정하지 마.”사내망만 있으면 됨
되는지부터 알아보기“실수로 번호가 크게 올라갔는데 되돌릴 방법이 있는지 찾아줘. 아무것도 바꾸지 말고 조사만 해줘.”조사만 하므로 쓰기 권한 불필요

요청할 때 이렇게 하면 결과가 좋아요

  • 조사와 실행을 나눠서 말하세요. “일단 조사만”이라고 하면 아무것도 저장하지 않습니다. 결과를 보고 “이대로 반영해줘”라고 하면 그때 씁니다.
  • 기준이 되는 파일을 알려주세요. “내가 고친 엑셀 기준으로”처럼 무엇을 따라야 하는지 말하면 엉뚱한 판을 쓰지 않습니다.
  • 브라우저 로그인은 직접 해 주세요. Claude가 로그인을 부탁하면 Edge에서 로그인한 뒤 “로그인 완료”라고 답하면 이어서 진행합니다.
  • 전자서명·최종 승인과 실제 시험 수행은 사람이 합니다. Claude는 시험하지 않은 TC에 Passed를 넣지 않습니다.

ALM에서 실제로 맡길 작업과 결과 예시

이슈 등록·수정·댓글에는 본인 PC의 개인 PAT를 사용합니다. TC·Test Run·문서 등 화면 작업에는 로그인된 Edge·Chrome과 Computer Use를 사용합니다. 요청한 작업을 저장한 뒤 같은 ID에서 결과를 확인합니다.

아래 결과는 보고 형식 예시이며 현재 작업의 완료 사실이 아닙니다. 대괄호 안에는 이번 작업에서 확인한 값을 넣습니다. 항목을 펼치면 필요한 입력부터 완료 기준까지 볼 수 있습니다.

1. Checklist를 새 버전 TC와 미서명 문서로 등록

이전에 요청한 V1.1.0 Checklist 신규 TC 이관 업무를 재구성

준비할 입력

  • 최신 Checklist 파일·대상 시트·버전·등록할 A~K 범위와 보존할 실행 이력
  • 로그인 브라우저·ALM 프로젝트·대상 Space·표준 문서·현재 Import 템플릿

복사해서 사용할 요청

ALM과 VXvue 스킬로 최신 서버 Checklist의 [버전/시트]를 확인하고, 로그인된 Edge의 [프로젝트]에 A~K 정의를 신규 TC로 등록해줘.
기존 결과·버전·Issue 이력과 원래 빈 행은 보존해줘. 새 TC와 원본 행의 대응을 남기고 Preview에서 여러 Step이 하나의 TC로 묶이는지 확인해줘.
Import·SRS verifies 연결·[표준 문서] 기준 문서 편입·전체 재조회까지 진행해줘. 전자서명 없이 검토 가능한 문서까지 정리해줘.

수행할 범위

  1. 현재 서버 자료 판과 원본 해시·시트·행·등록 대상을 다시 확인한다. 예전 제외 목록을 그대로 쓰지 않는다.
  2. 현재 Import 열과 필수값을 확인하고 새 TC/Step 대응 자료를 만든다. Preview에서 묶음·Step/Expected·수량을 대조한 뒤 허용된 Import를 수행한다.
  3. 생성한 ID와 원본 행을 연결하고 문서 편입·실제 SRS 관계를 확인한다. 기존 정상 서비스 API가 허용된 경우에만 대량 관계 처리에 병행한다.
  4. 전체 대상의 속성·단계·Expected·문서 소속·관계를 다시 읽는다. 권한 제한과 불명확한 저장은 별도로 보고한다.

결과 보고 형식

원본: [파일 해시 / 시트 / 행 범위]
등록: [생성 ID ↔ 원본 행 / 요청·생성·재조회 수량]
문서: [URL / 유형 / 표지·개정 이력 / 미서명 상태]
관계: [TC ID → verifies → SRS ID / 저장 대조 결과]
미완료: [권한 제한·누락·미서명 단계]

완료 기준과 제한

  • 신규 Import와 Roundtrip을 구분한다. Old SRS ID 문자열만 적은 것은 관계 저장 완료가 아니다.
  • Import 성공·Coverage·기존 Pass는 제품 시험 통과 증거가 아니다. Test Data 공란은 근거 없이 채우지 않는다.
  • 원본이 바뀌면 기준본과 차이를 보고하고, 응답이 끊기면 생성 여부부터 조회해 중복 Import를 막는다.
2. 기존 TC의 속성과 Step·Expected 수정

일반 브라우저 실행 요청 예시

준비할 입력

  • 수정할 실제 TC ID·변경 전후 문구·수정할 필드
  • 문서 상태·편집 권한·신규 생성인지 기존 갱신인지

복사해서 사용할 요청

로그인된 Chrome의 [프로젝트]에서 [TC ID 목록]의 [변경할 필드]만 첨부한 전후표대로 수정해줘.
기존 ALM ID·문서 소속·Step/Expected 대응·실행 이력은 유지하고, 저장 후 같은 ID 전체를 다시 열어 대조해줘.
Excel을 사용하면 신규 Import가 아니라 기존 ID를 유지하는 Roundtrip인지 먼저 확인해줘.

수행할 범위

  1. ID로 현재 항목과 상태·원래 값을 확인한다. 이미 값이 바뀌었으면 전후표와 충돌을 확인한다.
  2. 전체 기존 TC를 JSON으로 읽고 위치별 허용 변경 목록과 비교 도구로 수정 준비본을 검사한다. Roundtrip이면 내보낸 ID·행 구조와 현재 매핑을 보존한다.
  3. 저장 뒤 같은 ID의 전체 변경값·변경하지 않은 단계·관계·이력을 동일 허용 목록으로 다시 대조하고 추가 생성 여부를 확인한다.

결과 보고 형식

대상: [TC ID / URL]
변경: [필드 / 이전 값 / 저장된 값]
보존: [단계 수·Step/Expected 대응·문서·실행 이력]
재조회: [전체 대상 대조 결과 / 불명확한 항목]

완료 기준과 제한

  • 수정안을 제안해 달라는 요청만 받았다면 저장하지 않는다.
  • 뜻이 바뀐 TC에 과거 Pass를 새 결과로 가져오지 않는다.
3. TC와 SRS의 실제 관계 연결

Checklist 이관에서 요청한 verifies 관계 작업을 재구성

준비할 입력

  • TC↔SRS 매핑표·프로젝트·제품·버전·기존 관계
  • 관계 방향과 추가/교체 범위

복사해서 사용할 요청

ALM 스킬로 로그인된 Edge의 [프로젝트]에서 첨부 매핑의 TC와 SRS를 연결해줘.
TC의 verifies와 SRS의 is verified by 방향을 확인하고 기존 정상 관계는 유지해줘.
저장 뒤 양쪽 ID의 관계를 다시 읽어 요청한 매핑 전체와 대조해줘.

수행할 범위

  1. 양쪽 실제 ID와 제품·버전·기존 관계를 읽고 연결할 의미가 맞는지 확인한다.
  2. 요청한 방향으로 관계를 저장한다. 잘못된 기존 관계 삭제는 별도 요청 범위를 확인한다.
  3. 양쪽 저장 관계와 요청 매핑을 대조하고 Coverage 표시와 실제 관계 저장을 구분해 보고한다.

결과 보고 형식

매핑: [TC ID → verifies → SRS ID]
역방향: [SRS ID → is verified by → TC ID]
대조: [요청 / 기존 유지 / 추가 / 미저장 항목]
제품 커버리지 판단: [별도 검토 결과 또는 미검토]

완료 기준과 제한

  • SRS ID의 존재만으로 해당 TC가 충분한 시험인지 확정하지 않는다.
  • 403 등으로 읽지 못한 값은 공란이라고 단정하지 않고 현재 값 확인 불가로 남긴다.
4. Test Run 초안 생성과 포함 TC 확인

일반 브라우저 실행 요청 예시

준비할 입력

  • 프로젝트·Run 이름·템플릿·Plan Scope·대상 TC 목록
  • 대상 빌드·파라미터·실행 환경·초기 상태

복사해서 사용할 요청

ALM 스킬로 현재 로그인된 [브라우저]의 [프로젝트]에 [Run 이름] 초안을 만들어줘.
[템플릿]·[Plan Scope]·첨부 TC 목록·[빌드/환경]을 사용하고 생성 후 실제 포함 ID를 양방향 대조해줘.
시험은 수행하지 않았으므로 Passed나 실행 결과는 입력하지 마.

수행할 범위

  1. 템플릿과 Plan Scope·현재 TC 목록을 확인하고 중복 Run 여부를 조회한다.
  2. 요청한 설정으로 Run을 생성한다.
  3. 같은 Run ID를 다시 열어 포함/누락/초과 TC와 파라미터·초기 상태를 확인한다.

결과 보고 형식

Run: [생성 ID / URL / 이름]
범위: [Plan Scope / 요청·포함·누락·초과 TC]
환경: [빌드 / 파라미터 / 실행 환경]
상태: [재조회한 초기 상태 / 시험 결과 미입력]

완료 기준과 제한

  • 템플릿 예시를 현재 프로젝트의 필수값으로 단정하지 않는다.
  • Run 초안 생성은 실제 시험 수행이나 제품 Pass가 아니다.
5. 근거가 있는 Issue 등록 또는 지정 항목 수정

기존 이슈 초안 작성 흐름을 실제 등록 요청으로 확장한 예시

준비할 입력

  • Actual 캡처·로그·재현 절차·발생 버전·Expected 근거
  • 등록 프로젝트·유형·담당자·연결할 TC/Run·기존 유사 이슈·본인 PC의 개인 PAT 설정

복사해서 사용할 요청

VXvue 스킬로 첨부 현상의 Expected와 기존 유사 이슈를 먼저 확인하고, ALM 스킬로 내 PC의 개인 PAT를 사용해 [프로젝트]에 Issue를 등록해줘.
제공한 Actual과 재현 절차를 쓰고, 사양 출처는 SRS ID만 적어줘. 확인하지 않은 원인·횟수·등급은 확정하지 마.
제목·본문·버전·담당자·첨부·[TC/Run] 연결을 저장하고 생성 ID에서 다시 확인해줘.

수행할 범위

  1. 실제 관찰과 문서상 Expected·미확인을 나누고 기존 유사 이슈를 확인한다.
  2. 등록 범위와 필요한 값이 확인된 뒤 사용자 PC의 개인 PAT로 요청한 Issue를 생성하거나 지정 ID만 수정한다.
  3. 저장된 제목·본문·버전·첨부·관계와 ID를 재조회한다.

결과 보고 형식

Issue: [ID / URL / 신규 또는 수정]
근거: [Actual 증거 / Expected 출처 / 미확인 원인]
저장 확인: [제목·본문·버전·담당자·첨부·관계]
미완료: [권한 또는 자료 부족]

완료 기준과 제한

  • 초안만 요청한 경우에는 등록하지 않는다. 근거가 불충분하면 결함 확정 대신 확인 필요로 보고한다.
  • 메일 발송·다른 이슈 상태 변경은 이 요청에 포함하지 않는다.
6. 표준 문서 구성과 미서명 상태 정리

Basic Function 기준 문서 정리 요청을 재구성

준비할 입력

  • 대상 Space·문서명·유형·포함 Work Item 목록
  • 참조할 표준 문서·표지·결재표·개정 이력·현재 결재경로 권한

복사해서 사용할 요청

ALM 스킬로 [표준 문서]를 참고해 [대상 Space]에 [문서명]을 구성하고 첨부 TC ID를 순서대로 넣어줘.
표지·결재표·개정 이력과 실제 결재경로 속성은 각각 확인해줘.
전자서명을 하지 않은 검토용 문서까지 정리하고 목차·Heading·포함 ID를 저장 후 재조회해줘.

수행할 범위

  1. 현재 문서 유형과 표준 문서의 구조를 확인한다. 결재표 본문과 실제 approvalType 같은 속성을 구분한다.
  2. 요청한 표지·Heading·항목 편입을 수행하고 문서를 저장한다.
  3. 포함 ID 전체·순서·목차·표지·현재 미서명 상태를 확인한다.

결과 보고 형식

문서: [URL / 유형 / Space]
구성: [Heading / 포함 ID / 순서 대조]
결재: [표지 결재표 / 실제 경로 조회 결과 / 미서명 상태]
남은 작업: [권한 부족 설정 / 사용자 검토·서명]

완료 기준과 제한

  • 권한이 없어 읽지 못한 결재경로는 빈 값으로 보고하지 않는다.
  • 표지 정리와 최종 결재 완료는 다르다.
7. 제공한 시험 증거를 지정 Run에 기록

사용자의 “검증했어·수정확인했다” 후속 요청을 재구성

준비할 입력

  • 실제로 수행한 버전·TC·조건·Actual·증거·판정
  • 대상 Run·Iteration·Step별 결과·Issue와 과거 이력

복사해서 사용할 요청

첨부한 수행 증거를 VXvue 스킬로 기존 TC와 대조하고, ALM 스킬로 [Run ID]의 [TC/Iteration]에 이번 결과를 기록해줘.
내가 준 조건과 결과만 사용하고 과거 Fail·재발생 기록은 유지해줘.
Step별 결과와 전체 상태를 구분해 재조회하고, 증거가 부족한 항목은 입력을 보류해줘.

수행할 범위

  1. 현재 Run·버전·TC·Iteration을 확인하고 실제 증거와 판정 기준을 대조한다.
  2. 허용된 이번 실행 기록만 입력하고 증거와 Issue를 연결한다.
  3. 같은 실행 기록의 Step·전체 상태·증거·이력 보존을 확인한다.

결과 보고 형식

실행 대상: [Run / TC / Iteration / 빌드]
기록 근거: [실제 수행 조건 / Actual / 증거]
저장 결과: [Step별 결과 / 전체 상태 / Issue]
보류: [증거 또는 판정 기준이 부족한 항목]

완료 기준과 제한

  • 개발팀 수정 완료·Coverage·문서 작성만으로 Passed를 입력하지 않는다.
  • 사용자가 “검증했어”라고만 하면 무엇을 어떤 조건에서 확인했는지 자료와 현재 기록으로 먼저 확인한다.
8. 실행 전에 절차와 필요한 자료만 물어보기

설명·조사 전용 요청 예시

준비할 입력

복사해서 사용할 요청

ALM 스킬로 신규 Import와 Roundtrip의 차이, 준비할 파일과 Preview에서 확인할 내용을 알려줘.
이번에는 설명과 근거 조회만 하고 브라우저의 기록을 변경하지 마.

수행할 범위

  1. 현재 자료 판의 관련 장·슬라이드·영상 근거를 읽는다.
  2. 업무 차이와 필요한 입력·실행 시 확인할 항목을 정리한다.
  3. 현재 운영 설정을 확인하지 못한 부분과 아직 수행하지 않은 작업을 알린다.

결과 보고 형식

설명: [절차 차이 / 선택 기준]

완료 기준과 제한

  • 설명 질문을 등록 요청으로 확대하지 않는다.
  • 자료 해시 검증은 현재 ALM 설정이나 작업 성공을 증명하지 않는다.

설치하기 (Claude 데스크톱 앱 기준)

먼저, 어느 탭에서 쓰나요?

Claude 데스크톱 앱에는 Chat·Cowork·Code 탭이 있습니다. ALM에 실제로 등록·수정하려면 Code 탭을 사용하세요. Code 탭은 내 PC에서 실행되기 때문에 내 PC에 저장한 개인 PAT와 사내망을 그대로 쓸 수 있습니다.

탭ALM 스킬로 할 수 있는 일추천
Code교육 자료 조회, 개인 PAT로 이슈·TC·SRS 관계·Test Run 기록 쓰기, 로그인된 브라우저 화면 작업(Computer Use 같은 브라우저 제어 연결이 켜져 있을 때), 엑셀 정리실제 작업은 여기서
Cowork업로드한 스킬로 절차 설명, 문안·엑셀 준비. 실행 환경에 따라 내 PC 환경 변수와 사내망에 닿지 않을 수 있습니다.준비·검토용
Chat업로드한 스킬로 사용법 설명과 문안 작성. 인터넷 쪽 실행 환경이라 사내 ALM·QA 서버에 닿지 않습니다.질문용

예전에 사내망 밖 실행 환경의 AI 채팅에서는 DNS 접근 제한 때문에 ALM 쓰기를 하지 못했고, 같은 작업을 사내 PC의 로컬 실행에서 마쳤습니다. 등록·수정 작업은 처음부터 Code 탭에서 시작하세요.

Code 탭에 설치하는 순서

  1. 준비물을 확인합니다.

    회사 계정으로 로그인한 Claude 데스크톱 앱, 사내망(또는 VPN), Python 3이 필요합니다. 시작 메뉴에서 PowerShell을 열고 py --version을 입력해 Python 3.x가 나오면 됩니다.

  2. 스킬 ZIP을 받습니다.

    이 페이지 위쪽의 ALM 스킬 다운로드를 누르면 다운로드 폴더에 alm-skill.zip이 저장됩니다.

  3. 스킬 폴더에 풉니다.

    PowerShell에 아래 한 줄을 붙여 넣고 Enter를 누릅니다. 폴더가 없으면 자동으로 만들어집니다.

    Expand-Archive "$env:USERPROFILE\Downloads\alm-skill.zip" "$env:USERPROFILE\.claude\skills" -Force

    끝나면 %USERPROFILE%\.claude\skills\alm 폴더 안에 SKILL.md, scripts, server.json이 보여야 합니다. 직접 고쳐 둔 alm 폴더가 이미 있으면 덮어쓰기 전에 다른 곳에 복사해 두세요.

    명령 대신 파일 탐색기로 하기

    Win+R를 누르고 %USERPROFILE%\.claude\skills를 입력해 엽니다. 폴더가 없다고 나오면 %USERPROFILE%\.claude 안에 skills 폴더를 새로 만듭니다. ZIP을 열어 안에 있는 alm 폴더를 그대로 끌어다 놓습니다. alm\alm\SKILL.md처럼 한 번 더 겹치면 인식되지 않습니다.

  4. ALM에 쓰기까지 하려면 개인 PAT를 저장합니다.

    조회와 질문만 할 거라면 건너뛰어도 됩니다. 방법은 아래 개인 PAT 설정에 있습니다.

  5. 앱을 완전히 종료했다가 다시 켭니다.

    창의 X 버튼만 누르면 앱이 작업 표시줄 오른쪽 트레이에 남아 있습니다. 트레이의 Claude 아이콘을 오른쪽 클릭해 종료(Quit)한 뒤 다시 실행해야 새 스킬과 PAT를 읽습니다.

  6. Code 탭에서 첫 요청을 합니다.

    Code 탭을 열고 작업 폴더를 하나 고릅니다(예: 문서 폴더). 아래처럼 요청하거나 /alm을 입력해 부릅니다. Claude가 명령 실행 허락을 물으면 내용을 보고 허용합니다.

    ALM 스킬 상태를 확인해줘. 교육 자료 판과 내 PC에 POLARION_TOKEN이 설정돼 있는지만 보고, 아무것도 바꾸지 마.

    스킬 버전, 자료 판, metadata_verified: true, PAT 설정 여부가 나오면 준비가 끝난 것입니다.

새 버전이 나오면 ZIP을 다시 받아 3번과 5번만 반복합니다. PAT는 다시 넣지 않아도 됩니다.

Codex 또는 터미널의 Claude Code에 설치하기
사용 도구Windows에서 둘 위치
Claude Code(터미널·데스크톱 Code 탭 공통)%USERPROFILE%\.claude\skills\alm
Codex%USERPROFILE%\.codex\skills\alm

macOS·Linux는 ~/.claude/skills/alm 또는 ~/.codex/skills/alm입니다. Claude Code에서는 /alm, Codex에서는 $alm으로도 부를 수 있습니다. 설치 후 새 세션을 시작합니다. 자료 연결은 아래 명령으로도 확인할 수 있습니다.

py -X utf8 "$env:USERPROFILE\.claude\skills\alm\scripts\knowledge.py" status

metadata_verified: true는 자료 목록과 본문 파일의 해시가 맞는다는 뜻입니다. ALM에서 실제로 저장해 본 결과는 아닙니다.

Chat·Cowork에 스킬 ZIP 올리기(설명·문안용)

Customize → Skills → + → Create skill → Upload a skill에서 ZIP을 올리고 켭니다. 계정에 Skills와 코드 실행이 허용돼 있어야 합니다. 올린 스킬은 절차 설명과 문안 작성에 쓰고, 실제 등록·수정은 Code 탭에서 합니다. Claude 공식 Skill 업로드 안내

개인 PAT 설정 (ALM에 쓰기 위해 꼭 필요)

본인 PAT를 실제로 쓰는 PC의 환경 변수에 넣어야 ALM 쓰기가 됩니다. 공용 QA 서버는 자료를 읽기만 합니다. 이슈 등록·수정·댓글, TC·SRS 관계·Test Run 기록 같은 쓰기는 각자 PC에서 각자의 PAT로 ALM에 직접 요청하므로, ALM 기록에도 본인 이름으로 남습니다.

  • PAT가 없으면 ALM이 401(인증 필요)로 거절합니다. 같은 요청에 PAT를 넣으면 정상으로 읽힙니다.
  • PC를 바꾸거나 다른 PC에서도 쓰려면 그 PC에도 따로 저장합니다.
  • 스킬은 PAT가 있는지만 확인하고 값을 화면·채팅·파일에 남기지 않습니다.
  1. ALM에서 PAT를 발급합니다.

    ALM(Polarion)에 로그인해 오른쪽 위 내 계정(My Account) 화면의 Personal Access Token 항목에서 새 토큰을 만듭니다. 이름(예: claude-alm)과 만료일을 정하고, 만들어진 토큰을 복사합니다. 닫으면 다시 볼 수 없을 수 있으니 바로 다음 단계로 넘어갑니다.

  2. 내 PC에 저장합니다.

    시작 메뉴에서 PowerShell을 엽니다(관리자 권한 아님). 아래 명령을 붙여 넣고 Enter를 누른 뒤, Polarion PAT 입력 칸에 복사한 토큰을 붙여 넣고(마우스 오른쪽 클릭) 다시 Enter를 누릅니다. 입력한 값은 *로 가려집니다.

    $s = Read-Host 'Polarion PAT' -AsSecureString; [Environment]::SetEnvironmentVariable('POLARION_TOKEN', [Net.NetworkCredential]::new('', $s).Password, 'User')

    Windows 기본 PowerShell(5.1)과 PowerShell 7 모두에서 동작합니다.

  3. 저장됐는지 확인합니다.

    아래 명령의 결과가 True면 저장된 것입니다. 토큰 값은 표시되지 않습니다.

    [bool][Environment]::GetEnvironmentVariable('POLARION_TOKEN','User')
  4. Claude 데스크톱 앱을 완전히 종료했다가 다시 켭니다.

    켜져 있던 앱은 새 환경 변수를 모릅니다. 트레이 아이콘에서 종료한 뒤 다시 실행합니다.

  5. 읽기로 먼저 시험합니다.
    ALM 스킬로 내 PC의 개인 PAT가 동작하는지 [VP 번호] 하나만 읽어서 확인해줘. 아무것도 바꾸지 마.
이럴 때이렇게 하세요
토큰이 만료됐거나 새로 발급했어요2번 명령을 다시 실행해 새 값으로 덮어쓰고 앱을 다시 켭니다.
이 PC에서 더 이상 쓰지 않아요[Environment]::SetEnvironmentVariable('POLARION_TOKEN', $null, 'User')로 지우고, ALM의 Personal Access Token 화면에서도 토큰을 폐기합니다.
403(권한 없음)이 나와요PAT는 맞지만 내 계정에 그 프로젝트의 생성·수정·댓글 권한이 없는 경우입니다. ALM 관리자에게 권한을 요청합니다.

지켜 주세요. PAT를 채팅창에 붙여 넣거나 메신저·메일·파일에 저장하지 않습니다. 여러 사람이 같이 쓰는 PC에는 저장하지 않고, 다른 사람의 PAT를 빌려 쓰지 않습니다. 이슈 본문과 댓글의 사양 출처는 VP-480처럼 SRS ID만 적고, 게시된 댓글은 고칠 수 없으니 Claude가 보여 주는 게시 직전 문안을 확인합니다.

로그인된 Edge·Chrome에서 실제 작업하기

구체적인 등록·수정 작업을 요청하면 AI가 현재 로그인된 브라우저에서 대상을 확인하고 작업한 뒤 저장 결과를 다시 읽도록 스킬에 절차를 넣었습니다. 실행 환경에 Computer Use 도구가 연결되어 있어야 합니다.

요청할 수 있는 작업완료할 때 확인할 것
TC 생성·속성·단계 수정대상 ID·기존 값 보존·저장된 내용·중복 여부

Excel Import와 결과 기록Preview·처리 결과·대상 ID·실제 수행 증거
  1. 사용할 브라우저와 프로젝트, 대상 TC·Issue·문서 및 바꿀 값을 알려줍니다.
  2. AI가 현재 서버·프로젝트·상태를 읽고 요청 범위를 확인합니다.
  3. 허용된 작업을 수행한 뒤 같은 ID를 다시 열어 저장값을 확인합니다.
  4. 변경 전후와 저장 결과, 미수행·확인 불가 항목을 보고합니다.

요청 예시: 현재 로그인된 Edge의 ALM에서 지정한 TC 목록으로 Test Run 초안을 만들고, Plan Scope와 포함된 TC ID를 확인해줘.

실제 실행 증거 없이 Passed를 입력하거나 전자서명을 대신하지 않습니다. 전자서명은 사용자가 직접 처리합니다. 이미 요청한 범위의 일반 저장마다 허락을 반복해서 묻지 않으며, 삭제 등 별도 확인이 필요한 행동은 사용하는 컴퓨터 제어 도구의 정책을 따릅니다.

운영 Checklist의 신규 Import·실제 SRS 연결·미서명 문서 표시에서 확인한 절차를 반영했습니다. 다른 프로젝트·버전·권한은 실행할 때 다시 확인하며 제품 시험 결과를 대신하지 않습니다. 브라우저 연결이나 창·화면 식별이 불확실하면 입력하지 않고 중단합니다. 새 자동화 프로필로 바꾸거나 로그인 정보를 추출하지 않습니다.

Checklist를 새 버전 문서로 등록하기

ALM Skill 1.2.0은 최신 원본 대조부터 Excel 매핑·Preview·Import·SRS verifies 연결·문서 정리·저장 후 전체 대조까지 안내합니다. VXvue는 제품 스킬과 함께 현재 Basic Function 문서의 표지·결재표·개정 이력을 참조합니다.

  1. 원본 파일·버전·시트·등록 범위와 현재 ALM 필드를 확인합니다. 준비만 요청하면 실제 등록은 진행하지 않습니다.
  2. 등록을 요청하면 승인한 범위에서 파일·Preview·등록·문서 편입을 진행합니다. 많은 SRS 관계는 기존 연결에서 지원하는 일괄 방법으로 처리합니다.
  3. 모든 생성 ID·필드·단계·Expected·문서 소속·관계를 다시 읽어 원본과 대조합니다. 작업 중 원본이 바뀌면 이미 등록한 기준본과 차이를 구분합니다.
  4. 표지 결재표와 실제 결재경로 설정을 각각 확인합니다. 권한이 없는 설정은 미완료로 알리고 전자서명·최종 승인은 사용자가 직접 합니다.

ALM과 VXvue 스킬로 최신 서버 Checklist의 [대상 버전]을 검토하고 A~K만 신규 등록해줘. SRS verifies 연결과 Basic Function 기준 미서명 문서 정리, 저장 후 전체 대조까지 진행해줘.

현재 Skill ZIP을 다시 설치하면 새 절차가 적용됩니다. 브라우저·API 연결과 권한은 실행 환경마다 확인하며, 지난 작업의 개수·ID·제외 목록을 다음 버전에 그대로 사용하지 않습니다.

설명과 근거를 물어볼 때

아래 답변 요점은 서버 가이드에서 확인한 사례입니다. 현재 운영 설정과 제품 시험 결과는 별도로 확인합니다.

ALM 스킬로 TC를 Roundtrip 수정할 때 기존 ALM ID를 지워도 되는지 근거와 함께 알려줘.

기존 항목을 갱신하려면 내보낸 ALM ID와 행 구조를 보존합니다. Import 후 같은 ID에 수정이 반영됐는지, 불필요한 새 TC가 생기지 않았는지 확인합니다.

자료를 사용할 때 알아둘 점

  • 교육 자료의 작성 시점과 현재 서버 설정은 다를 수 있습니다. 문서 유형·상태 이름·허용 Action·권한은 현재 ALM에서 확인합니다.
  • 영상은 시간별 화면 표본을 대조했습니다. 음성 전체 전사와 표본 사이의 모든 클릭 확인은 포함하지 않았습니다.
  • 공용 서버의 조회 도구는 읽기 전용입니다. 이슈 쓰기는 개인 PAT를 사용하는 로컬 REST API에서, 브라우저를 지정한 작업은 기존 로그인 화면에서 처리합니다. 시험 결과는 실제 수행 증거에 따라 기록하며 전자서명은 사용자가 처리합니다.
  • 서버 자료의 해시가 맞지 않으면 조회를 중단합니다. 오래된 로컬 자료로 바꿔 읽었다고 처리하지 않습니다.

앱을 완전히 종료하지 않아 예전 환경 변수를 쓰는 경우가 많습니다. 확인 명령이 True인지 보고 앱을 다시 켭니다. 그래도 401이면 토큰이 만료됐거나 잘못 붙여 넣은 것이니 새로 발급해 다시 저장합니다.

Chat·Cowork에서 요청했다면 Code 탭에서 다시 요청합니다. Code 탭이라면 사내망·VPN 연결을 확인합니다.
자료 버튼이 활성화되지 않습니다
사내망 또는 VPN과 QA 서버 연결을 확인하고 “다시 불러오기”를 누릅니다. 실패 중에는 확인되지 않은 자료 링크를 열지 않습니다.
스킬 이름이 보이지 않습니다
압축을 푼 폴더가 alm/alm/SKILL.md처럼 중첩되지 않았는지 확인합니다. 설치 후 새 대화를 시작합니다.
Python 실행을 찾지 못합니다
Python 3 설치와 실행 경로를 확인합니다. 스킬이 실행되지 않아도 브라우저의 상세 가이드는 이용할 수 있습니다.
해시 불일치가 나옵니다
자료 갱신이 끝난 뒤 status를 다시 확인합니다. 계속 실패하면 자료 판과 오류를 운영 담당자에게 전달합니다.
현재 화면과 교육 자료가 다릅니다
