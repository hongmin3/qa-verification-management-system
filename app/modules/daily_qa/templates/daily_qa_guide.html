무엇을 하나요

운영 서버가 평일 아침마다 Polarion 에서 VXvue 사양(SRS)과 이슈를 읽고, 수집된 TC·매뉴얼과 비교해 QA 가 검토할 초안을 만듭니다. 초안은 Claude(회사 Team 계정)가 VXvue QA 규칙(Rev1.17)에 맞춰 작성하고, 사람이 이 화면에서 승인·거절합니다.

구분언제하는 일결과
사양 변경 영향 검토매일, SRS 가 바뀐 날바뀐 SRS 를 가리키는 기존 TC 마다 유지·경미 수정·수정 필수·신규 TC 필요·사양 확인 필요 판정Finding
이슈 수정확인 초안매일, 새 이슈가 있는 날이슈 유형 분류. Program Fixed 만 수정확인·Regression TC 초안Finding + 영향성평가 Checklist 형식 Excel 초안
사양–TC 연결 점검매주 지정 요일TC 없는 SRS, 삭제된 SRS 를 가리키는 TC (AI 없이 계산)Finding
매뉴얼 누락 후보 점검매주 지정 요일 또는 매뉴얼이 바뀐 날지난 7일 바뀐 SRS 가운데 매뉴얼 반영이 빠졌을 수 있는 후보Finding(후보)

검토하는 법

  1. 아침 요약 메일의 링크로 들어오거나 검토 대기열을 엽니다.
  2. Finding(AI 가 낸 판정 한 건)을 눌러 근거 위치(SRS ID, TC 시트·행)를 원본과 대조합니다.
  3. 승인 / 거절 / 근거 추가 필요(메모 필수) 중 하나를 누릅니다. 결정은 이 시스템 안에만 저장됩니다.
  4. 승인한 초안은 사람이 원본 Checklist·Polarion 에 직접 반영합니다. 자동 반영 기능은 없습니다.
  5. 질문에 답하면 다음 날 실행에 반영됩니다.

상태가 이상할 때

  • 규칙 판 불일치: 수집된 QA 규칙 판이 Skill 기준과 다릅니다. Skill 을 새 판에 맞춰 고친 뒤 기준 판을 올려야 AI 단계가 다시 돕니다.
  • 건너뜀: Polarion 토큰·Claude 토큰 같은 설정이 없거나, 오늘 바뀐 항목이 없습니다. 실행 상세의 비고를 보세요.
  • 실패: 비고에 첫 실패 이유(예: 사용량 한도)가 붙습니다. "SRS 수집이 실패해 검토하지 못했습니다"처럼 Polarion 조회가 실패한 날도 실패로 보입니다. 작업별 오류는 결과 파일 audit.json 에 있습니다.
  • 다음 실행으로 미룸: 실행당 작업 상한을 넘었거나 실패한 사양 변경·이슈는 다음 실행에 다시 들어갑니다. 이미 처리한 이슈는 다시 보내지 않습니다.

서버 설정·운영 명령은 저장소의 docs/modules/daily-qa.md 에 있습니다.
