Regression 영향 분석 사용법

3단계면 됩니다 — 등록하고, 올리고, 결과를 봅니다.

1. Knowledge 등록

Knowledge 메뉴에서 사양서(PDF·`.docx`)와 TC Excel(`.xlsx`)을 등록합니다. 매뉴얼은 지식 폴더로 올립니다.

  • 제품·버전은 목록에서 고르거나 새로 입력할 수 있습니다.
  • 같은 제품·버전에 서로 다른 문서를 여러 개 등록해도 이전 문서가 사라지지 않고 전부 유지됩니다. 잘못 등록했으면 목록에서 "삭제"로 지울 수 있습니다(되돌릴 수 없으니 확인 후 삭제하세요).
  • 파일은 클릭으로 선택하거나 끌어다 놓아도 됩니다.

2. 분석 실행

분석 메뉴에서 제품만 고르고, 변경과 관련된 문서(변경 내역서, 설계검토보고서, 리비전 히스토리, 사양서 개정판 등 무엇이든, 여러 개 동시 첨부 가능)를 올리거나, 문서 없이 "사용자 요청 사항"에 원하는 내용을 직접 적어도 됩니다.

  • 사양서·TC 파일을 따로 고를 필요가 없습니다 — 선택한 제품에 등록된 사양서·TC를 전부 자동으로 검색합니다.
  • 내부적으로 기준 사양서와 실제로 달라진 부분만 골라내 분석하므로, 이미 있던 내용을 "변경"으로 오인하지 않습니다.
  • "사용자 요청 사항"에 적은 내용은 업로드한 문서보다 우선하는 근거로 반영됩니다. 문서와 요청 사항을 함께 써도 됩니다. 요청 사항이 있으면 문서 전체 대신 관련성 높은 부분만 추려 분석해 AI 토큰 사용량도 줄어듭니다.
  • 실행 중에는 실제 진행 단계({{ stages|join(' → ') }}, 모두 {{ stages|length }}단계)와 경과 시간이 진행률 표시줄로 실시간 표시됩니다. AI가 응답을 기다린다고 임의로 퍼센트가 올라가지 않고, 실제로 그 단계에 도달했을 때만 올라갑니다. 실패하면 어느 단계에서 왜 실패했는지 바로 보여줍니다.

3. 결과 확인

보고서는 Analysis Overview(분석 기준 정보) → Change Summary(변경사항을 의미 단위로 정리) → Impact Analysis(영향 영역) → Recommended Regression TC → 필요한 경우 신규 TC 제안 → 주의사항 순서로 구성됩니다.

  • 영향도: HIGH(우선 검증) · MEDIUM · LOW · NONE(영향 없음) · 확인 필요(정보 부족으로 AI가 단정하지 못한 경우)
  • AI 확신도: 0~100%로 표시되며, 정확한 통계적 확률이 아니라 AI가 해당 TC와 변경사항의 연관성을 판단한 상대적 신뢰도입니다.
  • 선정 이유에 실제 사양서 근거가 있으면 "근거: 사양서명 · 항목 · 페이지" 형태로 함께 표시됩니다(내부 ID가 아니라 사람이 읽을 수 있는 형태로 변환됨).
  • 기존 TC로 다루지 못하는 변경이 있으면 신규 TC 초안(.md)이 함께 생성됩니다. 근거 없는 항목은 "확인 필요"로 비어 있으니 QA가 채워서 실제 TC에 반영합니다.
  • HTML Report·XLSX는 분석 화면과 분석 이력에서 바로 받을 수 있습니다.

VXvue 사양서 자동 동기화

VXvue 최신 사양서는 별도 자동화(Polarion 연동)가 매주 월요일 수집한 결과를 Windows 작업 스케줄러가 같은 날 07:30에 자동으로 Knowledge에 반영합니다(이전 리비전은 자동 삭제). Knowledge 화면의 "동기화 상태" 카드에서 마지막 동기화 시각과 결과를 확인할 수 있습니다. 자세한 구조는 docs/AUTOMATION.md를 참고하세요.

비용 관리

분석 1건당 AI 호출은 정확히 1번이고, 동일한 입력으로 다시 분석하면 캐시로 처리돼 비용이 들지 않습니다. config.yaml의 analysis.daily_token_limit에 값을 넣으면 하루 누적 토큰이 그 값을 넘을 때 새 분석 실행을 막습니다(상단 배너에서 사용량 확인 가능).

AI 결과는 후보 추천이며 최종 QA 판단을 대체하지 않습니다.

이 프로그램을 직접 설치하거나 다른 서버에 배포하려면 docs/DEPLOYMENT.md를 참고하세요.
