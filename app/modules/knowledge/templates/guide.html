Knowledge 사용법

여기서 등록·수집한 문서를 QA Agent · Regression 영향 분석 · 매뉴얼 개정 검증이 함께 씁니다. 세 기능이 서로 다른 문서를 보면 같은 변경에 대해 다른 결론이 나오므로, 문서는 한 곳에서만 관리합니다.

근거 수준은 QA 규칙이 정한 정보 우선순위입니다. 숫자가 작을수록 강한 근거이고, 매뉴얼까지만 Expected Result를 확정할 수 있습니다. 기존 TC나 연구소 Comment는 탐색 단서입니다.

1. 권장 방식 — 제품 지식 폴더 수집

제품마다 최신본을 모아 두는 폴더 하나를 정해 두고, 그 폴더를 읽어서 수집합니다. 파일을 하나씩 올리는 것보다 이 방식을 권합니다.

  1. QA가 관리하는 폴더에 최신본을 갈아끼웁니다. 앱은 그 폴더를 읽기만 하고 쓰지 않습니다.
  2. Knowledge 화면 상단 “지금 수집”을 누릅니다.
  3. 결과 알림에 등록·미변경·구버전 정리·중복 확인 필요 건수가 나옵니다.

리비전은 파일명에서 읽습니다

  • (260907) — 날짜 리비전 (사양서)
  • V1.0.11, V1.0.12W1 — 버전 리비전 (매뉴얼)
  • Rev1.12 — Rev 리비전 (QA 규칙)
  • RA16-148-002, R-20-643 — 사내 문서번호이며 리비전이 아닙니다
  • _KO / _EN — 언어. 같은 문서의 한국어·영어본은 서로 다른 문서로 봅니다
  • _확인완료, (개정) — 진행 상태 꼬리표. 문서 식별에서 제외합니다

같은 문서가 여러 개면 하나만 고릅니다

  • 리비전이 더 최신인 것을 고릅니다. 사양서1(260831)과 사양서1(260907)이 있으면 후자만 씁니다.
  • 원본 형식이 추출본보다 우선합니다. PDF/DOCX/XLSX가 있으면 사람이 미리 뽑아둔 .txt는 쓰지 않습니다 — 추출본은 갱신을 잊기 쉽습니다(실제로 원본보다 2주 오래된 사례가 있었습니다).
  • 제외한 파일과 제외 이유가 기록됩니다. 판단을 되짚을 수 있어야 하기 때문입니다.

2. 서버에서 폴더에 접근할 수 없을 때

지식 폴더는 보통 QA 담당자 PC에 있고 운영 서버에는 없습니다. 그 경우 화면에 “접근할 수 없습니다”가 표시되고 버튼이 나오지 않습니다. 폴더가 있는 PC에서 CLI로 실행하세요.

python scripts/sync_product_knowledge.py --dry-run                       # 무엇이 수집·제외되는지 미리 확인
python scripts/sync_product_knowledge.py --product VXvue                 # 수집 + 등록
python scripts/sync_product_knowledge.py --report-to http://서버:12000    # 서버 sync 로그에도 보고

그 PC의 작업 스케줄러에 걸어 두면 매주 자동 수집됩니다. 앱 안 스케줄러도 같은 시각에 시도하되, 폴더에 접근할 수 없으면 조용히 건너뜁니다.

3. 개별 파일 등록 (수동)

지식 폴더에 없는 문서를 한 건만 올릴 때 씁니다.

  • 사양서/Manual 등록 — PDF 또는 Word(.docx)
  • Test Case 등록 — XLSX. 컬럼 자동 탐지에 실패하면 수동 매핑 화면이 뜹니다. 시트·헤더 행·컬럼을 지정하면 그 설정이 저장돼 다음 분석에도 쓰입니다.

사양서1~5처럼 서로 다른 문서를 같은 제품에 여러 개 등록해도 이전 문서를 대체하지 않습니다. 등록된 모든 문서가 항상 검색 대상입니다 — “최신 1개만” 방식은 과거에 오판으로 확인돼 뒤집힌 규칙입니다.

4. TC Excel이 어떻게 읽히는가

  • 다중 시트를 전부 읽습니다. TC ID 컬럼이 있는 시트만 대상입니다.
  • TC마다 파일명 · 시트명 · 실제 Excel 행 번호를 기록합니다. 결과에서 근거를 누르면 원본에서 바로 찾아갈 수 있어야 하기 때문입니다.
  • 같은 TC ID가 중복되면 처음 것만 씁니다.
  • 버전별 수행 결과·비고 컬럼은 AI에 보내지 않습니다. 판정에 쓰지 않는 정보입니다.
  • 등록된 TC 파일을 시스템이 수정하지 않습니다. TC ID·행 순서·시트 구조·결과 이력을 건드리지 않습니다.

5. 등록 후 확인

  • QA Agent 화면 상단에 사양서·TC 건수와 QA 규칙 Rev가 표시됩니다. 0건이면 그 기능이 실행되지 않습니다.
  • 규칙 구현현황에서 수집된 규칙이 Skill별로 몇 절 잡혔는지 볼 수 있습니다.
  • 등록 문서 중 파싱에 실패한 것이 있으면 분석 결과에 “읽지 못한 문서”로 표시됩니다. 전체가 실패하지는 않습니다.

6. 새 제품 추가

  1. 이 화면에서 새 제품 추가로 제품명을 등록합니다.
  2. config/products/<slug>.yaml을 만들고 knowledge_source.dir에 그 제품의 지식 폴더 경로를 넣습니다. 기존 파일을 복사해 경로만 바꾸면 됩니다.
  3. “지금 수집”을 실행합니다.

파일명 규약이 같으면 코드 변경이 필요하지 않습니다. VXvue와 Bellalun Viewer가 같은 규약을 쓰고 있어 그것을 기준으로 삼았습니다.

7. 사내 문서는 어디에 저장되는가

  • 수집된 원본 사본과 정규화 텍스트는 data/product_knowledge/<제품>/에 있습니다.
  • 이 경로는 Git에 포함되지 않습니다. 저장소에는 코드와 스키마만 올라갑니다.
  • AI에는 원본 파일이 아니라 검색으로 추린 발췌만 나갑니다. 실제 전송 내용은 각 분석 결과 화면의 감사 영역에서 원문 그대로 확인할 수 있습니다.
