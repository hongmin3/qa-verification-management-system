검증 자료 관리 사용법

1. 검증 자료 관리 란

QA Agent · 매뉴얼 개정 검토 · 일일 QA 점검이 함께 쓰는 제품 자료 한 곳입니다. 기능마다 다른 문서를 보면 같은 변경에 다른 결론이 나오므로 자료는 여기서만 관리합니다.

문서 판 보관소가 아닙니다. 같은 문서는 최신 판 하나만 분석에 쓰고, 서로 다른 문서(예: Operation Manual 과 Service Manual)는 각자 최신 판 하나씩 남습니다.

2. 제품 상태 확인

현황판의 제품 카드 머리에 상태가 보입니다.

상태뜻
정상꼭 필요한 자료가 모두 있고 쓸 수 있습니다.
주의꼭 필요한 자료가 없거나, 일부를 읽지 못했거나, 오래 갱신되지 않았습니다. 분석은 되지만 결과가 부족할 수 있습니다.
오류마지막 수집이 실패했거나 꼭 필요한 자료를 하나도 쓸 수 없습니다.

카드의 줄에 마우스를 올리면 그 상태가 나온 이유가 보입니다.

3. 자동 자료와 수동 자료

제품 설정 파일이 자료마다 어디서 들어오는지(출처)를 정합니다. 등록·교체 버튼은 출처가 사람이 등록인 사양서·매뉴얼·Test Case 에 나옵니다. 자동 출처라도 설정에 화면 등록 허용(allow_manual: true)이 있으면 같은 버튼이 나옵니다. 예를 들어 VXvue 사양서는 ALM 자동 수집을 그대로 하면서, ALM 이 만들지 않는 VSS Specification 같은 사양서를 화면에서 등록·교체·삭제할 수 있습니다.

출처들어오는 길화면에서 할 수 있는 일
ALM 자동담당자 PC 가 평일 아침 ALM 사양서를 올립니다.상태와 마지막 동기화 시각만 봅니다.
외부 자동화다른 자동화 도구가 보냅니다.상태만 봅니다.
지식 폴더담당자가 제품 지식 폴더에 파일을 넣으면 매일 08:00 에 서버로 올라갑니다. 바로 올리려면 상세 화면의 지금 수집을 누릅니다.상태와 수집 제외 목록을 봅니다.
사람이 등록제품 상세 화면에서 올립니다.새 문서 등록, 교체, 삭제.

4. 파일 교체

  1. 현황판에서 제품의 상세보기를 엽니다.
  2. 바꿀 문서 줄의 교체를 누르고 새 파일을 고릅니다. 다른 문서를 더하려면 구역 아래 새 문서 등록을 씁니다.
  3. 새 파일이 문제없이 등록된 뒤에만 이전 문서가 빠집니다. 새 파일을 읽지 못하면 등록하지 않고 기존 문서를 그대로 씁니다.
  4. 파일 이름으로 보면 다른 종류인 파일은 받지 않습니다. 예를 들어 (매뉴얼) 로 시작하는 파일은 사양서 구역에 올릴 수 없습니다.
  5. 교체로 올린 파일은 바꿀 문서의 이름 형식으로 등록됩니다. 예를 들어 (사양서) VSS Specification (261006).xlsx 의 교체로 VSS_spec_최종.xlsx 를 올리면 (사양서) VSS Specification (오늘 날짜).xlsx 가 됩니다. 올린 이름에 같은 형식의 날짜·버전이 있으면 그 값을 씁니다. 새 문서 등록은 올린 이름을 그대로 씁니다.
  6. 화면에서 삭제한 문서는 지식 폴더에 같은 파일이 남아 있어도 다음 수집이 다시 등록하지 않습니다. 날짜·버전이 다른 새 판은 등록합니다. 지운 문서를 되살리려면 같은 이름의 파일을 화면에서 다시 등록합니다.

자동 출처 구역에서 교체한 문서도 다음 자동 수집이 더 새로운 판을 올리면 그 판이 최신이 됩니다. 화면 등록은 자동 수집을 멈추지 않습니다.

지식 폴더 지금 수집

  1. 지식 폴더 안의 파일을 바꿉니다.
  2. 제품 상세 화면 위쪽의 지금 수집을 누릅니다. 폴더 전체를 그 시점 그대로 다시 수집합니다.
  3. 서버가 폴더를 직접 볼 수 없으면 수집 요청을 남깁니다. 담당자 PC 가 1분 안에 요청을 보고 폴더를 올립니다. 올리기가 끝나면 화면이 저절로 새로 고쳐집니다.
  4. 버튼 옆에 수집 요청 대기 중이 계속 보이면 담당자 PC 가 꺼져 있는지 확인합니다.

버튼 대신 폴더가 있는 PC 에서 아래 명령을 실행해도 됩니다. 아무것도 하지 않으면 매일 08:00 예약이 올립니다.

python scripts/sync_product_knowledge.py --product "VXvue" --upload-to http://<서버 주소>:24357

5. 문제 상태가 보일 때

상태 문구할 일
자료 없음그 자료를 등록하거나 지식 폴더에 넣습니다.
파싱 실패파일이 깨졌거나 비어 있습니다. 상세 화면에서 읽지 못한 문서를 확인하고 다시 저장한 파일로 교체합니다.
수집 실패상세 화면의 마지막 동기화 문구로 원인을 보고, 담당자 PC 의 예약 작업이 돌았는지 확인합니다.
업데이트 필요오랫동안 수집에 성공하지 못했습니다. 담당자 PC 의 예약 작업을 확인합니다.
종류 확인 요청파일 이름으로 보면 다른 종류인 문서가 이 구역에 있습니다. 사람이 올린 등록이면 그 줄의 삭제로 뺍니다. 자동 출처 구역이어도 사람이 올린 줄에는 삭제가 보입니다.
중복 확인 요청같은 문서의 판이 두 개 이상 등록돼 있습니다. 하나만 남깁니다.

지식 폴더에 넣었는데 분석에 안 쓰이는 파일은 상세 화면의 수집 제외를 펼치면 왜 빠졌는지와 대신 쓰는 파일이 보입니다.

6. 새 제품 추가

화면에서 제품을 더하지 않습니다. 제품 설정 파일(config/products/<제품>.yaml)을 먼저 만들고 앱을 다시 띄우면 현황판에 카드가 생깁니다. 순서는 docs/PRODUCT_ONBOARDING.md 에 있습니다.
