매뉴얼 개정 검증 사용법

개정본을 등록하고, AI의 1차 검토 결과를 QA가 확정한 뒤, Comment가 삽입된 Word 파일을 내려받습니다.

1. 검증 등록

매뉴얼 검증 화면에서 제품, Manual 종류, 제품 버전(예: 1.1.0)을 입력하고 Word Track Changes가 켜진 .docx 또는 .pdf를 첨부합니다.

  • 리비전 표기는 직접 입력하지 않습니다. 제품 버전과 검증 회차로 V1.1.0 · W1처럼 자동으로 만들어지며, 입력 칸 아래에서 미리 볼 수 있습니다.
  • 재검증이라면 "이전 검증"에서 앞 리비전을 선택합니다. 회차가 하나 올라가고(W2, W3 …), 앞 회차에 Word Comment 파일로 보낸 지적사항이 결과 화면에 다시 나옵니다. 같은 계보에서는 제품 버전을 바꿀 수 없습니다.
  • PDF는 첫 파일을 이전 검증 없이 Baseline으로 등록한 뒤, 다음 PDF부터 그 이전 PDF를 선택해 비교합니다. 페이지 텍스트 차이에는 항상 사람 확인이 필요합니다.
  • Release Note와 설계검토보고서를 선택적으로 첨부할 수 있습니다. 첨부하지 않으면 같은 제품 버전으로 등록된 최신 문서를 재사용하고, 같은 버전 문서가 없으면 Release 대조를 하지 않습니다.
  • 최신 SRS는 Knowledge와 사양서 동기화가 관리하는 공용 문서 저장소의 제품 사양서를 재사용하며, 별도로 다시 업로드하지 않습니다.
  • 오늘 쓴 AI 토큰이 하루 한도(analysis.daily_token_limit)를 넘으면 새 검증을 시작할 수 없습니다.

2. 결과 확인과 QA 판정

문서의 Track Changes를 변경 한 건씩 뽑고, 페이지 번호·목차 점선·저작권 표기 같은 단순 변경은 목록에만 남긴 채 AI 판정에서 뺍니다. 나머지 변경마다 관련 SRS 근거를 찾아 AI가 1차 판정합니다.

  • 판정은 문제없음, 보강 필요, 수정 필요, 삭제 필요, 누락 의심, 사양 확인 필요, 문서 버전 확인 필요, 판정 불가 가운데 하나이며 근거와 함께 표시합니다.
  • 그림이 바뀐 변경은 글자만으로 판단할 수 없으므로 "Human Review 필요"가 붙습니다. AI가 문제없음으로 판정해도 판정 불가로 바뀌고 Word Comment에도 들어갑니다.
  • Release Scope에는 있지만 매뉴얼 변경에서 찾지 못한 내용은 “누락 의심”으로 따로 표시합니다.
  • 같은 제품의 다른 매뉴얼에 반영이 필요해 보이는 항목은 "다른 Manual 영향 확인" 칸에 후보로 나옵니다. QA가 영향 있음 / 영향 없음으로 확정합니다. 매뉴얼 서버 연동이 켜져 있으면 매뉴얼 서버의 Current 매뉴얼도 함께 대조합니다.
  • AI 결과는 최종 결정이 아닙니다. QA가 판정을 변경하고 사유를 남기면 AI 원본과 QA 결정을 함께 보존합니다.

3. Word Comment 결과 다운로드

결과 화면에서 Word Comment 삽입 DOCX 생성을 누르면 문제 항목의 원본 위치에 QA Comment 초안이 추가된 파일을 받을 수 있습니다. 원본 Track Changes와 기존 Comment는 유지됩니다.

  • 파일에 넣은 Comment는 이 리비전의 지적사항으로 저장됩니다. 다음 회차 검증 결과 화면의 "이전 Round 미해결 지적사항"에서 해결됨 / 미해결 / 재오픈 / 제외를 확정합니다.
  • 같은 리비전으로 파일을 다시 만들어도 이미 저장한 지적사항은 겹쳐 저장하지 않습니다.

4. Claude 대화로 돌리는 방법

변경마다 판정을 보며 바로 고치고 싶을 때는 이 저장소에서 Claude Code를 열고 "D:/manual/VXvue_UserManual_Rev1.8.docx 매뉴얼 분석해 줘. 릴리스 노트는 D:/manual/RN_1.1.docx"처럼 말합니다.

  • Claude는 작업 설명서 vxvue-manual-revision-review를 따라 scripts/manual_review_local.py의 extract로 변경과 사양서 근거 후보를 뽑고, 변경마다 판정한 뒤 요약을 보여 줍니다.
  • 판정을 고치고 싶으면 대화로 말합니다. 확정하면 Claude가 finish를 실행해 결과 Excel과 Comment를 넣은 Word 파일을 output/manual_review_local/에 만듭니다.
  • 사양서는 이 PC의 지식 사본(data/product_knowledge/)에서 읽습니다. 결과는 이 앱의 검증 이력에 남지 않습니다. 다음 회차에는 이번 결과 폴더의 comments.json을 함께 넘기면 이전 지적사항을 이어받습니다.

현재 지원 범위

  • 지원: DOCX Track Changes(삽입·삭제·이동), PDF 페이지 텍스트·이미지 비교, 회차 계보와 이전 지적사항 참고 판정, SRS 근거 검색, Release Scope 누락 의심, 다른 Manual 영향 후보(매뉴얼 서버 연동 포함), 이미지 변경 사람 확인, QA 재판정, DOCX Word Comment 생성, Claude 대화 검증
  • 지원하지 않음: 서식 변경(글꼴·문단 모양) 추출, 머리글·바닥글·각주 안의 변경, PDF 리비전의 Word Comment 생성, 사양서 원본의 취소선·밑줄 시각 확인(근거의 시각 확인 상태는 항상 미확인)

AI 검토는 QA 판단을 보조하며 최종 승인이나 사양 확정을 대체하지 않습니다.
