매뉴얼 개정 검토 사용법

개정 매뉴얼 파일 하나를 끌어놓으면 AI가 1차 검토합니다. QA는 결과 화면에서 바로 확인·확정하고, 연구소에 보낼 Comment 삽입 Word 파일을 내려받습니다.

1. 검증 등록

매뉴얼 개정 검토 화면에 Word Track Changes가 켜진 .docx 또는 .pdf 파일 하나만 끌어놓습니다.

  • 파일 이름으로 제품, 매뉴얼 종류, 제품 버전을 자동 인식해 "자동 인식" 줄에 보여 줍니다. 예: (매뉴얼) VXvue Service Manual.V1.1.0W2_KO.docx → VXvue · VXvue Service Manual · V1.1.0.
  • 같은 제품·매뉴얼·버전의 완료된 검증이 있으면 자동으로 이어받아 회차가 하나 올라갑니다(W2, W3 …). 이어받는 미해결 지적사항 수도 함께 보입니다.
  • 값이 틀리면 "인식 값 고치기"를 펼쳐 바꿉니다. 파일 이름의 버전이 제품 버전이 아닌 문서(예: DICOM Conformance Statement V4.4)는 등록된 제품 버전을 제안하고 메모를 남깁니다. 같은 계보에서는 제품 버전을 바꿀 수 없습니다.
  • PDF는 첫 파일을 Baseline으로 등록하고, 다음 PDF부터 그 이전 PDF와 자동으로 비교합니다. 페이지 텍스트 차이에는 항상 사람 확인이 필요합니다.
  • Release Note와 설계검토보고서는 "참고 자료 추가 (선택)"에 있습니다. 첨부하지 않으면 같은 제품 버전으로 등록된 최신 문서를 재사용하고, 같은 버전 문서가 없으면 Release 대조를 하지 않습니다.
  • 근거 사양서 줄에 사양서 개수·날짜·최근 동기화가 보입니다. 지식 폴더에 더 새 사양서가 있거나 동기화가 실패했으면 경고가 붙습니다. 사양서는 Knowledge와 사양서 동기화가 관리하는 공용 문서를 재사용합니다.
  • 오늘 쓴 AI 토큰이 하루 한도(analysis.daily_token_limit)를 넘으면 새 검증을 시작할 수 없습니다.

2. 결과 확인과 QA 확정

결과는 파일로 내려받지 않고 결과 화면에서 바로 봅니다. 변경은 세 묶음으로 나뉘고, 맨 위 탭에 건수가 보입니다.

  • 연구소 요청: 보강·수정·삭제 필요, 누락 의심, 문장 점검에 걸린 변경. QA 확인: 사양 확인·문서 버전 확인 필요, 판정 불가, 사람 확인이 필요한 그림·PDF 변경. 문제없음, 그리고 페이지 번호·목차 점선 같은 단순 변경.
  • 카드마다 위치(절 제목 · 문단 번호), 변경 글자와 최종 문장, 문제·QA Comment 초안·권장 문구, 근거 사양서가 보입니다. 확신도와 판정 신호는 "자세히"에 있습니다.
  • AI 판정이 맞으면 동의, 다르면 판정 바꾸기에서 판정과 사유를 저장합니다. 화면을 다시 읽지 않고 묶음 건수와 QA 확정 수가 바로 바뀝니다. AI 원본 판정은 따로 보존됩니다.
  • 남은 AI 판정 모두 동의는 QA가 아직 확정하지 않은 변경에 AI 판정을 한꺼번에 넣습니다. 사람 확인이 필요한 변경과 문장 점검에 걸린 변경은 빠지므로 직접 확인하세요.
  • AI 판정은 VXvue QA 작성 규칙 가이드의 문서 개정 검토 기준을 따릅니다. 공통 절이나 다른 공식 문서에서 이미 설명하는 내용, 대상 독자에게 필요 없는 내부 구현은 누락으로 잡지 않습니다. 사양서끼리 맞지 않으면 "사양 확인 필요"로 둡니다.
  • 문장 점검은 AI 없이 같은 단어 반복, 추가 문구 중복, 문장 붙음, 문장부호 겹침, 공백 겹침을 찾습니다. 번호 오류는 Word 자동 번호가 글자에 없어 보지 않으니 원본에서 확인하세요.
  • 그림이 바뀐 변경은 AI가 문제없음으로 판정해도 판정 불가로 바뀌고 Word Comment에도 들어갑니다.
  • 누락 의심, 다른 Manual 영향, 이전 회차 지적사항은 아래 접힌 칸에 건수와 함께 있습니다. 다른 Manual 영향은 QA가 영향 있음 / 영향 없음으로 확정합니다. 매뉴얼 서버 연동이 켜져 있으면 Current 매뉴얼도 함께 대조합니다.

3. 연구소 회신용 Word 파일 받기

결과 화면의 Comment 넣은 Word 받기를 누르면 문제 항목의 원본 위치에 QA Comment 초안과 문장 점검 내용이 추가된 파일을 받습니다. QA가 문제없음으로 확정한 변경에는 Comment가 붙지 않습니다. 원본 Track Changes와 기존 Comment는 유지됩니다.

  • 파일에 넣은 Comment는 이 리비전의 지적사항으로 저장됩니다. 다음 회차 결과 화면의 "이전 회차 지적사항"에서 해결됨 / 미해결 / 재오픈 / 제외를 확정합니다.
  • 같은 리비전으로 파일을 다시 만들어도 이미 저장한 지적사항은 겹쳐 저장하지 않습니다.

4. Claude 대화로 돌리는 방법

변경마다 판정을 보며 바로 고치고 싶을 때는 이 저장소에서 Claude Code를 열고 "D:/manual/VXvue_UserManual_Rev1.8.docx 매뉴얼 분석해 줘. 릴리스 노트는 D:/manual/RN_1.1.docx"처럼 말합니다.

  • Claude는 작업 설명서 vxvue-manual-revision-review를 따라 scripts/manual_review_local.py의 extract로 변경과 사양서 근거 후보를 뽑고, 변경마다 판정한 뒤 요약을 보여 줍니다.
  • 판정을 고치고 싶으면 대화로 말합니다. 확정하면 Claude가 finish를 실행해 결과 Excel과 Comment를 넣은 Word 파일을 output/manual_review_local/에 만듭니다.
  • 사양서는 이 PC의 지식 사본(data/product_knowledge/)에서 읽습니다. 결과는 이 앱의 검증 이력에 남지 않습니다. 다음 회차에는 이번 결과 폴더의 comments.json을 함께 넘기면 이전 지적사항을 이어받습니다.

현재 지원 범위

  • 지원: 파일 이름 자동 인식, DOCX Track Changes(삽입·삭제·이동)와 절 제목, PDF 페이지 텍스트·이미지 비교, 회차 계보와 이전 지적사항 참고 판정, SRS 근거 검색과 사양서 최신 여부 경고, Release Scope 누락 의심, 다른 Manual 영향 후보(매뉴얼 서버 연동 포함), 이미지 변경 사람 확인, 문장 점검, 할 일 묶음과 QA 확정·일괄 동의, DOCX Word Comment 생성, Claude 대화 검증
  • 지원하지 않음: 서식 변경(글꼴·문단 모양) 추출, 머리글·바닥글·각주 안의 변경, PDF 리비전의 Word Comment 생성, 번호 오류 점검, 사양서 원본의 취소선·밑줄 시각 확인(근거의 시각 확인 상태는 항상 미확인)

AI 검토는 QA 판단을 보조하며 최종 승인이나 사양 확정을 대체하지 않습니다.
